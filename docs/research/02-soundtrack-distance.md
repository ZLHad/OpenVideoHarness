# 02 · 28 份配乐听起来太像：怎么量，怎么拉开

## 问题

28 个风格样片的配乐口味重叠：同一套减法合成器，28 份里 20 份是 150 BPM，全部单声道（数字见下面"做法"）。能不能用一个数说清"有多像"，再按这个数把它们拉开？

## 做法

- **量出来的症状**：旧配乐全部来自同一套减法合成器；28 份里 20 份是 150 BPM（120 BPM 的 5 份，90 BPM 的 3 份）；全部单声道；谱质心只在 102 Hz–1.2 kHz 之间。
- **特征向量**：每份取前 5 s，用 librosa 算 7 个量：谱质心（取对数）、起音率（每秒）、<250 Hz / 250 Hz–4 kHz 的能量占比、>4 kHz 的占比（取对数）、立体声宽度（side 与 mid 的 RMS 比）、打击乐占比（HPSS）。
- **距离**：把 7 个量按"旧配乐 28 份 + 引擎示范 28 份"这 56 份合在一起的均值和标准差做 z 分数，取欧氏距离。尺子固定不动，所以三组结果可以直接比。
- **三组**：**旧**（v0.2.1 的 28 份）；**示范**（引擎作者给每个风格写的一份粗糙示范，用的是 [#13](https://github.com/ZLHad/OpenVideoHarness/pull/13) 新加的乐器）；**重写后**（四位 agent 分头给 28 个样片重写的配乐）。
- **重写时的约束**：保持每个样片的 `bpm`、`meters` 和段落小节数（画面按这个网格卡点）；每个风格有一个别人不当主角的标志性乐器；同一家族里律动要不同；旧的 `layers` 只能在 synthwave-outrun、fui-hud、crt-terminal 里当配角；设计目标是最近邻距离不小于 1.2。
- **命令**（脚本目前不在仓库里）：

```bash
uv run --with librosa --with soundfile --with numpy python features.py <dir>    # <dir>/old/*.wav 与 <dir>/demos/*.wav → features.json，并打印统计
uv run --with librosa --with soundfile python ana.py feat slug=path.wav ...     # 新渲染的配乐到其他风格的最近邻
```

距离矩阵直接由特征表（每份配乐 7 个数）算出，不需要重新渲染音频；下面的两张新图是据此画的。用同一个配方重算，复现了 [#13](https://github.com/ZLHad/OpenVideoHarness/pull/13) 描述里的旧配乐与示范的数字（中位数 2.27 和 3.58，最近一对 0.52 和 0.87）。

来源：旧配乐和 28 份示范的特征表，重写后 28 份配乐的特征表，以及重写时的设计说明和写作要求（见上面"重写时的约束"）；这些是作者本地的文件，没有入库，特征的算法就是上面写的 7 个量，脚本没有入库。BPM 的统计数的是 `styles/*/score.json`。旧与示范的数字也见 [#13 的描述](https://github.com/ZLHad/OpenVideoHarness/pull/13)，重写后的数字也见 [#31 的描述](https://github.com/ZLHad/OpenVideoHarness/pull/31)。

## 发现

| | 旧配乐 | 引擎示范（#13） | 重写后 |
|---|---|---|---|
| 成对距离中位数 | 2.27 | 3.58 | 3.71 |
| 各风格到最近邻的距离，均值 | 0.80 | 1.64 | 1.78 |
| 最近一对 | 0.52 · bubble-chart-story / risograph | 0.87 · guochao-festive / synthwave-outrun | 1.22 · guochao-festive / scratched-type |
| 378 对里距离小于 1.0 的 | 40 | 2 | 0 |
| 小于 1.2 的 | 57 | 4 | 0 |
| 谱质心范围 | 102 Hz–1.2 kHz | 91 Hz–3.4 kHz | 186 Hz–3.0 kHz |
| 立体声宽度 | 全为 0（单声道） | 0.02–0.74 | 0–0.58（一份单声道） |
| 起音率（每秒） | 2.0–9.6 | 1.2–14.2 | 1.4–14.0 |

![旧配乐与重写后配乐的 28×28 距离矩阵，按家族排列，越暗越像](figs/02-distance-matrices.zh.png)

*图 1 · 28×28 的成对距离，按样片家族排列；越暗越像，白点是小于 1.2 的一对，圈出的是各自最近的一对。*

**1. 引擎先抬高了中位数，重写再抬高了下限。** 用新乐器和立体声写的示范（每个风格一份），把中位数从 2.27 抬到 3.58，最近一对从 0.52 抬到 0.87；重写 28 份配乐之后，中位数只再涨 0.13，但最近一对到了 1.22，小于 1.2 的对从 4 个变成 0 个。拉开的主要是最挤的那几对，而不是平均水平。

**2. 下限的提升靠的是立体声宽度。** 去掉宽度这一项、只用其余 6 个特征：旧配乐不变（它们的宽度恒为 0），示范的中位数 3.43、最近一对 0.78，重写后的中位数 3.33、最近一对 0.74（dark-math / risograph），小于 1.2 的对有 9 个。也就是说在 6 个特征上，重写后并不比示范更分散。

**3. 距离被两三个特征主导。** 重写后的集合里，打击乐占比占了成对平方距离总和的 33 %（旧配乐里只有 2 %），高频占比 17 %，起音率 14 %，立体声宽度 13 %。打击乐占比的 z 标准差只有 0.045，宽度是 0.152，所以它们的一点点差别在 z 空间里被放得很大。

## 因此改了什么

- [#13](https://github.com/ZLHad/OpenVideoHarness/pull/13)：给 `bin/vh music` 加了 `parts`（[`tools/audio/instruments.py`](../../tools/audio/instruments.py)）：77 个合成乐器（无采样）、一套音型写法、立体声和混响总线；每个声部必须能听见，否则渲染报错。它的"Spread"表就是旧配乐对示范的那一栏。
- [#16](https://github.com/ZLHad/OpenVideoHarness/pull/16)：重写配乐时撞出来的引擎问题（网格不整除小节时丢音、段落参数对单音声部无效、`gain_db` 的含义、古琴泛音过响）。
- **重写本身**在 [#31](https://github.com/ZLHad/OpenVideoHarness/pull/31)：28 个样片的 `score.json`、STYLE.md 的"声音"段，重渲的 `swatch.mp4` 和带声音的 gallery。WIP 提交说明里还没做完的三件，#31 里做了：用 #16 之后的引擎重渲，ink-wash 古琴泛音的力度（0.12 → 0.85），重做带声音的 gallery（`bin/vh style gallery --mp4`）；另外有 7 个样片的音效电平按 `qa` 的结果调过。
- 重写用的规则是上面"重写时的约束"里那几条：一个风格一个标志性乐器、同家族律动不同、旧 layers 只当配角、最近邻不小于 1.2。
- 算距离的脚本还不在仓库里。要不要做成 `bin/vh` 下的检查（例如新样片入库时给出它的最近邻），是个没定的问题。

来源：PR #13、#16、#31 的描述；重写时的设计说明（没有入库）。

## 局限与没解决的

- **只有 7 个统计量、5 s 片段。** 它们看不到旋律、和声，也看不到"这是不是同一种乐器"。没有记录逐对的听测结论，表里的数是仪表读数，"拉开了"只是指这把尺子上的距离。
- **尺子可以被优化。** 重写的 agent 手里有这个目标（最近邻 ≥ 1.2）和这套特征；上面第 2、3 点说明，立体声宽度和打击乐占比是最便宜的两个杠杆。
- **最近的一对恰好是设计上最不同的两种声音**（guochao-festive：唢呐加 trap 节奏；scratched-type：金属敲击和工业节奏）。没人听过这一对；更可能是这把尺子分不开它们，而不是它们真的像，但这只是猜测。
- **节奏没拉开。** 为了让画面卡点不变，BPM 和拍号都保留了：主分支里 28 份仍是 20 份 150 BPM、5 份 120、3 份 90（#31 合并前后都是这个数）。#13 的描述和重写时的设计说明写的是"28 份里 18 份 150 BPM"，主分支的 `score.json` 数下来是 20 份，这两个数为什么不一致，没查清。
- **写笔记时，重写后那一栏还没用 #16 之后的引擎重渲**（WIP 提交说明写着要重渲），数字可能会动；那张特征表是谁、用什么命令生成的，文件里没有记录，配方按同一个特征脚本推断。后来 #31 在重渲后的最终配乐上重量了中位数和最近一对，数字没动（见"现状"）。距离的尺子只对这 56 份参照有意义，不能拿去和别的库比。

来源：重写时的设计说明和写作要求（没有入库）、[#13 的描述](https://github.com/ZLHad/OpenVideoHarness/pull/13)、`styles/*/score.json`、[#31 的描述](https://github.com/ZLHad/OpenVideoHarness/pull/31)。
