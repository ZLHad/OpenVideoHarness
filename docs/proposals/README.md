还没做的方向，写下来给维护者拍板。每篇写清楚：为什么提、看过什么、量过什么、建议怎么做、要谁定什么。提案不是规则：通过以后，按提案里分好的步骤一步一个 PR 去做，规则写进 `CLAUDE.md`、`playbook/` 或工具文档；没通过的留在这里，写上原因。

和 `docs/research/` 的区别：研究笔记记的是已经量过、已经因此改了仓库的事；提案记的是还要人定的事。
