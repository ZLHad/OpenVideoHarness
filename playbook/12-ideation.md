# 12 立意：先有点子，再有风格

这篇管片子的"点子"：一个让形式本身就在讲内容的装置。它排在流程的最前面，在定风格、挑配方、套类型默认值之前。叙事的形状（`09-narrative.md`）、开头的钩子（`10-hooks-and-packaging.md`）、风格预设（`styles/`）和镜头配方（`recipes/`），都是实现立意的工具。

- **适用**：所有类型、所有档位。`quick` 只做第 7 节最后一条的简版。
- **标记**：【综合】是本仓库从案例里归纳的做法，不是哪个来源的原话。例子出自 `cases/oneshot-five.md` 和 `cases/explainer-interstellar-blackhole.md`。

## 先说结论

1. **好片都有一个立意，风格在服务它**【综合】。`cases/oneshot-five.md` 拆的五支片子，从成片看，风格都在服务一个点子；创作顺序从成片看不出来，但先想点子、再定风格，至少不会让风格替代点子。
2. **立意从材料里长出来**：先挖素材（第 2 节），再想点子（第 3 节）；先自己想，再看别人怎么做（第 4 节）。
3. **底线不动，口味可以改**：底线照旧；风格预设、镜头配方、类型文档的节拍和语域、清单里没标【底线】的条目，都是默认值，立意需要时可以反着来，写一行理由（第 6 节）。
4. **关卡 ① 先定立意，再定风格**（第 7 节）。

## 1. 什么是立意

立意是一句话说得清的装置，它让片子的形式本身在讲内容。拿《你问 AI 一句话之后的 3 秒钟》来分层：

| 层 | 这支片子 | 换一个立意会怎样 |
|---|---|---|
| 题材 | AI 是怎么回答一个问题的 | 不变 |
| **立意** | 把回车之后的 3 秒放慢成 2 分钟，计时器和慢放倍数一直挂在屏幕上 | 全变 |
| 结构 | 按数据包的行程分段：出门、到机房、进模型、流回来 | 跟着立意变 |
| 风格 | 浅色粉彩 UI、彩色 token、细线 HUD | 跟着立意变 |

两个检验【综合】：
- **一句话说得出**。说不出，通常是还没想好，或者是好几个点子搅在一起。
- **换个题材就不成立**。"深色底、一个强调色、慢推镜头"换到哪个题材都成立，那是风格；"把 3 秒放慢成 2 分钟"只对"一瞬间里发生了很多事"的题材成立，那是立意。

一个立意通常会顺带定下几件事：贯穿全片的主体（BRIEF 的 Recurring motif）、首尾怎么呼应、至少一个别的片子没有的画面元素。

| 片子 | 立意 | 由它推出的东西 |
|---|---|---|
| 3 秒钟（科普） | 时间放大镜 | 常驻的计时 HUD；慢放倍数控制节奏；答完那一刻天变蓝 |
| 我眼中的你（肖像） | Claude 用第一人称讲它的用户，材料全是用户自己的记录 | 原话加出处，推断单独标注；"我不记得你"开头，"我又会忘记"结尾；暖黑底、宋体，慢 |
| Opus 5.5 自我介绍 | 用做法讲做法 | 讲到哪种技术，画面就用那种技术画 |
| FunTech showreel | 一个吉祥物穿过十几种风格世界 | 每 2 秒换一个世界，吉祥物和字标不变 |
| Mirage 发布片 | 产品的工作流就是故事 | 一个铬立方体从风景走到设计看板，再走到成片；拉远发现成片在一台显示器里 |
| 星际穿越·黑洞篇 | 一个黑洞贯穿全片 | 同一个着色器换机位反复用 |

## 2. 先挖素材

想点子之前，先把材料读一遍，在 `NOTES.md` 的"素材清单"里列 10–20 条**只属于这份材料**的东西：

- 数字，带单位和出处（"212 篇日记"，"0.08 秒到数据中心"）；
- 原话，照抄，注明出处和时间；
- 时间、地点、物件、界面（一次提交的哈希、一张真实的截图、一个文件名）；
- 矛盾和意外（"AI 每次都会忘记你"，"0.004 秒的事讲了 15 秒"）；
- 观众以为自己知道、其实可以被推翻的东西。

判断标准：换一个题目就没有了的东西。《我眼中的你》几乎每一句都有一条这样的素材，这是它能打动陌生人的原因。

- 用户只给了一句话、没有材料时，先查资料，数字和引文照硬规则 5 记出处。
- 材料是私人记录（日记、聊天、邮件、仓库）而片子要公开时，把会出现在画面里的原话、截图、人像先列给本人确认。

## 3. 发散：先自己想 5–8 个

- **这一步先不看** `styles/`、`recipes/`、类型文档的 Prompt 增量块（`bin/vh new` 把它贴在 BRIEF 末尾的 TYPE 一节）和案例。看过之后再想，点子会往看过的东西上靠【综合】。
- 每个点子一句话，写快，先不评判。第一个冒出来的通常是人人都会做的那个，写下来，让它别挡路，然后接着想。
- 至少一半的点子和画风无关：讲的是时间、视角、结构、证据、容器。

卡住的时候，可以拿下面几个问题撬一下。**这不是菜单**：最好的立意常常不在表上，从素材清单里直接长出来。

| 撬法 | 问自己 | 例子 |
|---|---|---|
| 换时间尺度 | 这件事真实发生得多快？放慢、加速、倒放会看到什么？ | 3 秒放成 2 分钟；一年压成 30 秒 |
| 换讲述者 | 谁最有资格讲？物件、数据、AI、对手、观众自己 | Claude 讲它的用户；一个声波讲自己被压扁 |
| 用做法讲做法 | 画面能不能本身就是证据？ | 讲到 Three.js，画面就是 Three.js 的场景 |
| 一个主体走完全程 | 有没有一个东西能从头跟到尾，一路在变？ | 7 个彩色 token；一个铬立方体 |
| 把答案变成画面 | 结论能不能字面地出现在画面上？ | 答完"天为什么是蓝的"，天就变蓝 |
| 换容器 | 能不能装进另一种媒介的外壳：游戏关卡、聊天记录、终端、说明书、病历、地图、账单 | FunTech 的关卡 HUD；`styles/pixel-16bit` 把事情讲成游戏系统 |
| 证据上屏 | 原话、出处、推断能不能分开摆出来？ | 原话下面注明哪次对话、几点几分，推断标【推断】 |
| 用一个矛盾做首尾 | 材料里有没有一个悖论，能开头抛出、结尾回应？ | "我都不记得你" ↔ "对话结束，我又会忘记" |
| 让数量有体感 | 一个数字能不能变成看得见的量？ | 154 格的日历只空了 3 格；`styles/isotype` |
| 给自己一个限制 | 全片只用一个镜头、一种颜色、一个物体？ | 一个黑洞着色器；`recipes/camera/one-take-world-travel.md` |

## 4. 看参照，再收敛成 2–3 张立意卡

自己的点子写下来以后，再打开参照，用来补强和校准，不是用来替换：

- 同类型的案例：类型文档"可参考的案例"一节、`cases/opus55-gallery.md` 第 3 节、`cases/oneshot-five.md`；
- 风格预设（`bin/vh style list`）、镜头配方和全片骨架（`bin/vh recipes list`）。第 1 节表里的五个立意已经写成了全片骨架：`recipes/sequences/` 的 time-dilation-replay、machine-eye-portrait、making-of-self、mascot-style-tour、workflow-as-story。拿来用时，换掉的是材料，不是立意的检验：它还得对你的材料成立。

然后收敛成 2–3 张**彼此拉得开**的立意卡，不是同一个点子的三个变体。至少一张不从风格预设出发。每张卡：

```text
立意 A：{一句话装置}
为什么是这份材料：{用到素材清单的哪几条；换个题目为什么就不成立}
主体：{从头跟到尾的东西，以及它怎么变}
首尾：{开头的画面或第一句话；结尾怎么回应}
画面：{由立意推出的语言：底色、字体、运动的语域、镜头；最接近的风格预设（可选）和要改的地方}
钩子：{开头几秒怎么抓人，常常就是立意本身；要发平台的片子按 10-hooks-and-packaging.md 写成钩子卡}
口味覆盖：{这张卡要反着用的默认（TASTE_CHECKLIST 的条号、Motion defaults、类型的语域或节拍），各一句为什么；没有就写"无"}
声音：{谁说话、配乐的语域、有没有一个声音母题}
风险：{最可能失败在哪；做不到时退到什么版本}
```

## 5. 好立意的检验

关卡 ① 自己先过一遍；成片的打分层里"立意"一项问的也是这几条（`templates/TASTE_CHECKLIST.md`）：

1. 一句话说得出吗？
2. 换个题材还成立吗？还成立，说明它只是风格。
3. 形式在讲内容吗？关掉声音看几帧，能不能猜出片子在讲什么？
4. 用到了素材清单里只属于这份材料的东西吗？
5. 看完以后，观众会跟别人转述哪一个画面或哪一句话？说不出来，就是还不够。
6. 做得出来吗？在选定的引擎和档位的时间里能不能实现？不能，就写清楚降到什么版本。

## 6. 立意和规则：底线不动，口味可以改

**底线**在任何立意、任何档位下都不动：每一帧是 t 的纯函数，事实照抄原文，字号和阅读时间的下限，片中不出现数字静音（有声片；用户要的无声片不带音轨，不适用），闪白频率，素材许可，不在文件里写 key。`TASTE_CHECKLIST.md` 里标了【底线】的条目也属于这一层。

**口味默认**是没有立意时的稳妥做法，立意需要时可以反着来：

- `TASTE_CHECKLIST.md` 里没标【底线】的条目；
- `BRIEF.md` 的 Motion defaults；
- 类型文档 Prompt 增量块里的语域、配色和节拍顺序；
- 风格预设、镜头配方和全片骨架。

反着来的规矩：

- **先说后做**：在写用到它的场景之前，写在立意卡的"口味覆盖"一行或 STYLE.md 上，同时记进 `DECISIONS.md`：改了哪条、立意为什么需要、翻案要花多少。
- **人批过的算人的**：关卡 ① 人选中的卡上写了的覆盖，算人的决定，reviewer 只查有没有做到。
- **之后加的由 reviewer 判**：关卡 ① 之后才加的覆盖（仍然要在写用到它的场景之前），reviewer 判断理由站不站得住：站得住，这一条记 PASS（覆盖）；站不住，照常判 FAIL。判了 FAIL 之后才补的覆盖一律不算。
- **理由要从立意出发**，"这样好看"不算。`quick` 没有 reviewer，交付时把覆盖的几行列给人看。

`cases/oneshot-five.md` 里站得住的例子：
- 书信体的肖像片，段落之间经黑场淡出再淡入、不叠字，一个画面常停 6–15 s（旁白在走）：段落之间是翻页，不是切换；
- 公司 showreel 用霓虹、铬面和多个饱和色：混搭本身就是要证明的"什么都能做"；
- 常驻的 HUD 读数（3 秒钟那支的计时和慢放倍数）：每个读数都在变、都承载信息，不是 #20 说的装饰。

**读数别贴着下限**：靠常驻读数讲答案的立意（HUD、仪表、标签），读数里要人读的部分用目标屏的联系表量过（BRIEF 的 `Watch on`）。`docs/research/06-concept-first-ab.md` 里一支横屏片的标签正好是 44 px：按 `desktop` 看够了，放进手机信息流（`feed`）只有约 8 px，评审是按信息流看的，读不出；只要求"看得出在走"的跑动数字不算。

FunTech 在终场前用了约 1 s 真静音。这碰的是底线，不在可改之列：要那种效果，做成"屏息"：留一层低音垫，镜头慢漂，不要声画一起停死（`playbook/04-audio.md`、TASTE_CHECKLIST #18）。

## 7. 在关卡 ① 怎么摆

- **一张卡定三件事**。审阅页的第一个决定是 `concept`：2–3 张立意卡，附推荐和理由。风格方向和钩子写在每张卡上（"画面""钩子"两行），选一张卡就一起定了；人可以在回复里换一个预设或换一个钩子。这样风格和钩子不会因为人没选推荐的那张而作废，关卡 ① 也不用再来一轮。人用导演模式单独点名 `style` 或 `hook` 时，选卡之后再出它们的选项。
- **人已经给了立意**（"把它做成一个游戏关卡"），就记进 BRIEF，不再出卡，最多附一个备选。
- **每张卡配一张图**。人看图比读文字快：`standard` 每张立意卡配一帧关键画面（草图、灰盒，或者 HyperFrames 的 `snapshot`）；`studio` 每张配一段 10–20 s 的草图，做法同 `01-pipeline.md` 的 look-dev；这段草图同时就是那种风格的小样。借来的预设，人想看真渲小样时放到 E0。
- **自由草图**（可选，一句话需求时推荐）：写立意卡之前，agent 可以先按自己最想做的那个点子，只守底线、不套任何默认值，渲一段 10–20 s 的草图，当作那张卡的图。它也能暴露模型自己的直觉，常常比套模板的版本更有意思。
- **`quick`**：写 3 个一句话点子，挑一个，在 `DECISIONS.md` 写一行为什么；风格从它推出来，可以借一个预设（`bin/vh style apply <preset> <project>`），也可以不借。

## 8. 例子：同一句需求，三张立意卡

需求："45 秒竖屏，讲多普勒效应（救护车开过去，音调变低）。"

| | 立意 | 画面和声音会怎样 |
|---|---|---|
| A | 时间放大镜：救护车开过的 2 秒放慢成 30 秒，声波一圈一圈画出来，频率读数常驻屏幕 | 俯视的街道，波纹在车前挤、车后拉开；读数是主体；声音跟着读数一路降调 |
| B | 换讲述者：一个声波用第一人称讲自己被追上、被压扁、又被拉长 | 角色化的波形，手绘；配音是这个声波；结尾它被拉成一条平线，安静下来 |
| C | 换容器：做成一个音乐 app 的波形编辑器，观众"拖动"救护车，音高跟着变 | 仿真 UI，大光标拖动；每次拖动都能听到音高变化；结尾把这个"工具"递给观众 |

三张卡讲的是同一个物理，出来的是三支完全不同的片子。默认的做法（扁平矢量加一个强调色、按"钩子 → 解释 → 例子"讲）可以作为第四个选项列在审阅页的附录里，供人对照。
