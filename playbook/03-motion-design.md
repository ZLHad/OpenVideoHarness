## 0. 没经过选择时最常见的样子

模型顺手做出来的视频，毛病高度一致。这些做法坏在没经过选择，不在做法本身：立意需要其中某一样时（书信体经黑场的慢淡入淡出、showreel 的霓虹和铬面、梗片的弹跳），照样可以用，规矩见 `12-ideation.md` 第 6 节。没有立意要求时，默认避开。想立意时，这张单子也是"同题的视频都长什么样"的一部分答案（`12-ideation.md` 第 3 节）：

- 什么都用 bounce/elastic 缓动，卡片在原地"呼吸"循环；
- 前 25% 把全部内容倒上屏，然后画面冻结；
- 场景之间一律 crossfade；
- 紫青渐变、玻璃拟态、Inter 字体、暗底光球；
- 字号按网页尺寸来，太小；
- 画面里满是标签、说明文字、写着剧情的牌子；
- 所有元素一个速度、一个缓动、同时入场；
- 事件一个压着一个，没有停顿。

来源之间有一处冲突：HyperFrames 的 house-style 建议装饰元素做 breathing，motion-doctrine 却禁止 idle wobble；ClaudeAnimationBase 则要求画面"永远不静止"。【综合】我的处理：overshoot、bounce、抖动、持续微动都算一种"语域"，在卡通、梗视频、MV 里用，不当默认值。默认用平滑的长尾缓动，静止也只能是刻意安排的停顿。

## 1. 缓动

| 用途 | 值 |
|---|---|
| 默认入场 | easeOutExpo `cubic-bezier(0.16,1,0.3,1)`；GSAP 用 `power3.out` 或 `expo.out` |
| 温和入场 | easeOutQuint `(0.22,1,0.36,1)`、easeOutCubic `(0.33,1,0.68,1)` |
| 位移、镜头运动 | easeInOutCubic `(0.65,0,0.35,1)`、easeInOutQuart `(0.76,0,0.24,1)` |
| overshoot（只在俏皮语域用） | easeOutBack `(0.34,1.56,0.64,1)` |
| 慢漂 | GSAP `sine.inOut` |
| 打字、计数 | `steps(N)` |
| 弹簧 | 阻尼比 ζ=1 无回弹；0.8–0.85 约 1–1.5% 回弹（iOS 感）；0.6–0.7 只用于俏皮；低于 0.55 不用。Remotion 里 `spring({damping:200})` 就是无回弹 |

方向规则：入场用 `.out`，出场用 `.in`，在两个位置之间移动用 `.inOut`。

弹簧还有两个进阶用法，都仍然是 t 的纯函数：

- **中途改目标：叠加弹簧。** 目标在 tᵢ 时刻换成新值时，不要从"当前位置和速度"重新起一段弹簧，那需要跨帧状态。改成把每次改动的增量 Δvᵢ 各接一段从 0 走到 1 的弹簧阶跃响应，全部加起来：

  v(t) = v₀ + Σ Δvᵢ · spring(t − tᵢ)

  v 是被动画的值，位置、缩放、颜色都可以。spring(τ) 在 τ ≤ 0 时为 0，起步时的变化率也是 0，所以叠上去速度不会突变；前一段还没走完的弹簧照样走完，中途改目标的运动是连贯的。

  ```js
  // ζ=1 弹簧的单位阶跃响应：τ≤0 为 0，之后平滑趋向 1；w 越大越快（w=12 约 0.5 s 到位）
  const spring = (tau, w = 12) => tau <= 0 ? 0 : 1 - (1 + w * tau) * Math.exp(-w * tau);
  const keys = [{ t: 0.0, x: 0 }, { t: 1.2, x: 400 }, { t: 1.5, x: 250 }];   // 1.5 s 时目标从 400 改成 250
  const x = (t) => keys.reduce((v, k, i) => v + (i ? (k.x - keys[i - 1].x) * spring(t - k.t) : k.x), 0);
  ```
- **前沿硬、后沿软：拉伸感。** 一个块从 A 移到 B 时，把它的前沿和后沿当成两个独立的弹簧：前沿的 w 大，后沿的 w 小（例如 18 对 10）。块在运动中顺着方向拉长，到位后后沿追上来，恢复原长。这就是第 3 节的"挤压与拉伸"，不用另写形变代码。

**弹簧按元素分档**：同一支片子里，同一类元素只用一档弹簧，不要每个按钮各调一套参数，手感才统一。下表四档来自 [xilo-opus-video](https://github.com/Kianzzz/xilo-opus-video) 的 `skills/xilo-opus-video/references/craft-rules.md`（MIT，提交 `f2cd828`），是社区经验值，作者没给测量依据，本仓库也还没实测过。回弹量和到位时间是按标准二阶弹簧算出来的，只帮你想象手感：

| 元素 | w（rad/s） | ζ | 回弹约 | 到位约（误差 2% 以内） |
|---|---|---|---|---|
| 按钮、开关、指示条的前沿 | 22–26 | 0.75–0.85 | 0.6–2.8% | 0.16–0.26 s |
| 卡片、容器、镜头 | 14–16 | 0.7–0.75 | 2.8–4.6% | 0.36–0.43 s |
| 大字、Logo 定版、3D 物体 | 9–11 | 0.85–1 | 0–0.6% | 0.38–0.65 s |
| 吉祥物、贴纸 | 16–20 | 0.4–0.5 | 16–25% | 0.40–0.53 s |

- 吉祥物一档的 ζ 低于上面缓动表"低于 0.55 不用"的下限，只在卡通、梗视频这类俏皮语域里用（见第 0 节）；卡片和镜头一档的回弹比 iOS 感略大，镜头看着晃就把 ζ 往 0.8 靠。
- xilo 的闭式解是欠阻尼公式，里面要除以 √(1−ζ²)。ζ 正好取 1 时 JS 会算出 NaN，被驱动的位置或尺寸失效，元素会消失或停在原处；ζ = 1 改用上面的临界阻尼式 `1 − (1 + wτ)·e^(−wτ)`。

## 2. 时间

- 单个元素入场不超过约 0.8s；出场约为入场的 75%；一组元素（卡片、图标、列表项）的 stagger 总长不超过约 0.5s。逐词出字不算在内，见下面逐词 stagger 一条。
- 第一个动画从 0.1–0.3s 开始，不要从 t=0 开始。
- 高潮前留 0.3–0.75s 的"戏剧逗号"。
- 速度表达重量：
  - 0.15–0.3s 急迫；
  - 0.3–0.5s 专业；
  - 0.5–0.8s 厚重；
  - 0.8–2s 电影感。
  
  最慢的场景应该是最快场景的 3 倍左右。
- 逐词 stagger 表达情绪：40ms 急促（适合短视频 hook），80ms 像对话，150ms 像纪录片，250ms 以上有仪式感。每个词至少可见 0.4s，整句出完再停 0.4–0.6s。
- 屏幕文字：
  - 同屏密度：英文不超过 8 个词；中文字幕每行不超过 16 字（Netflix 中文字幕规范，针对横屏）。竖屏的安全框只有 810px 宽，72px 字号每行最多 11 字，90px 最多 9 字。
  - 停多久：不写死秒数。读时分两层：底线只保证读一遍，舒服的时长跟着片子的节奏走。画面文字和短标签管的是最少在屏时间，字幕管的是读速上限，同一支片子里可以同时成立。时间都从字完整显示、动画停下那一刻算起（decode 字从定住算，见第 4 节）。
    - **底线：够快读一遍**（TASTE_CHECKLIST #5 的【底线】）：要观众读的画面文字至少停 max(1.5 s, 汉字数 ÷ 7 + 其他非空白字符数 ÷ 20 + 0.8 s)，中英双语取慢的那个。这就是介绍片 v5 逐帧量过的短标签规则（#53）；1.5 s 防一闪而过。20 个非空白字符约是 4 个英文词，20 字符/秒约合一分钟 240 词，是成人默读非虚构文字的平均速度（Brysbaert 2019 的元分析：238 词/分），也就是说只算读速的话，约一半人读不完一遍，所以加时不能省；7 字/秒是照同样的松紧给中文的假设，没有直接出处（跨语言的朗读常模给中文约 4.3 字/秒）。0.8 s 是眼睛找到字、落上去的时间。16 个汉字的一行约 3.1 s，4 字的标签 1.5 s。底线不随 Pace 变。
    - **目标：跟着 Pace 走**（默认口味，不是底线）：BRIEF 的 `Pace` 一行定全片的字读得多从容，默认 `normal`。目标从不低于底线。

      | Pace | 汉字/秒 | 其他字符/秒 | 另加 | 16 字一行 | 4 字标签 | 适合 |
      |---|---|---|---|---|---|---|
      | `relaxed` | 4.5 | 15 | 1.0 s | 4.6 s | 1.9 s | 讲解、论文、书信体、沉思：观众要边读边想 |
      | `normal` | 6 | 18 | 0.8 s | 3.5 s | 1.5 s | 大多数片子 |
      | `brisk` | 7 | 20 | 0.8 s | 3.1 s | 1.5 s | 快剪、梗、卡点 MV；就是底线 |

      - 数从哪来：`relaxed` 沿用旧规则的读速（lemo-opuscar `core/render/readcheck.mjs` 和 `DIRECTOR.md` §7 的 4.5 字/秒、15 字符/秒，MIT），找字时间从 1.5 s 降到 1.0 s，去掉了 2.5 s 的下限；`brisk` 就是底线，底线本来就是"快读一遍"，比它更快的目标永远够不着（起初提的 8 字/秒 + 0.3 s 在每个长度上都低于底线，所以并进了底线）；`normal` 的读速取两者之间，其他字符按同样的比例取 18，加时和底线一样是 0.8 s，这样三档在任何字数上都不交叉。三档都没有拿观众测过，是起点，不是定论；底线拿介绍片 v5 量过。
      - 一段可以和全片不一样：从容的片子里插一段快剪，或者反过来。HyperFrames 合成里在片段或场景上标 `data-pace="brisk"`（最近的标记生效），`texts.json` 里写 `"pace": "brisk"`。
      - 可以按 `brisk` 走的字：观众已经知道它说什么、扫一眼确认就够的，例如字幕说的正是画面刚演过的、术语卡第二次出现、片尾回扣开头的那句；还有镜头在走、只起提示作用的短标签（节点名、站名、关卡字幕），标 `data-read="label"`，不论 Pace 都按 `brisk`。拿不准算标签还是画面文字时，问一句：观众离开这一镜时要不要记住它？要记住就按画面文字。
      - 卡在音乐上的字：进出落在拍子或小节线上，停留按小节取，不为凑够目标的秒数补一截。离目标最近的那条小节线还不到底线，就往后多给一小节；过了底线、只是不到目标，就留着。
      - WARN 是提醒，不是返工单：`readcheck` 报 WARN 时看一眼是不是有意为之（卡在小节线上、重复的字、这一段本来就快），是就留着，不用记 `DECISIONS.md`。一大片都是 WARN，多半是 Pace 定错了，或者字太多：删字，或者改 BRIEF 的 Pace，不要逐条拉长。改 Pace 要在 `DECISIONS.md` 记一行；人点名要定 `rhythm`（剪辑节奏）时，改 Pace 先问人。
    - **字幕条**（跟着配音走）：中文不超过 9 字/秒，半角字符算半个；英文不超过 20 字符/秒，空格和标点都算（两个数都是 Netflix 对成人节目的规定）。每条至少 1.8 s（lemo 的 `DIRECTOR.md` §7）。字幕的时长本来由配音决定，所以不跟 Pace；这条抓的是一句里塞了太多字。一句念得短于 1.8 s 时，`bin/vh captions` 把它的结束时间往后延进后面的空隙（见 `playbook/04-audio.md`）。
    - **跟着旁白念的字幕，标 `data-read="subtitle"`**：画面上烧的字就是旁白的字，观众边听边核对，该按字幕的读速算，不该按画面文字算。HyperFrames 合成里给这样的片段标 `data-read="subtitle"`（标在片段上，或标在包着它的片段、场景上），`bin/vh readcheck index.html` 就用字幕的规则查它：输出里带 `sub` 标记，和别的文字一起算进总数。没标的仍按画面文字查，旁白没念的标题、标注、数字卡不要标；`data-read="onscreen"` 可以在被标的场景里把某一条改回去。导出的 `texts.json` 里是 `"read": "subtitle"`，手写的列表也认。
    - 为什么字幕和画面文字不一样【综合】：字幕和声音同时到，观众是在核对刚听到的话，读速上限可以高（中文 9 字/秒）；画面文字没有声音帮忙，观众要先在画面里找到它再读，所以底线用快读一遍的速度（7 字/秒），另加 0.8 s 找字。
    - 检查：`bin/vh readcheck <texts.json | 项目 | index.html>`。Pace 从项目的 BRIEF 读，`--pace` 可以临时换一档；低于底线报 FAIL（退出 1），只低于目标报 WARN（退出 0）；`--mode subtitle` 查字幕。输入是 `[{text, start, end}]`，`bin/vh captions` 写的 `captions.json` 可以直接用；它只看时间，字有没有被裁出画面要看联系表。还没写字时，`bin/vh readcheck --budget <秒>` 算一段时间里放得下多少字。
    - **为什么不写死秒数**【实测】：介绍片 v5 为了让每条标签都过旧规则 max(2.5 s, 汉字数 ÷ 4.5 + 其他字符数 ÷ 15 + 1.5 s)，一轮轮拉长停留，片长 87.5 → 150.5 s，人看完说"文字显示后的停顿太长了……但也不是那种一闪而过的"。改成只给短标签读一遍的时间、逐帧量过只补真正一闪而过的那几条以后，片长 103 s，人认可了节奏。下一支 `studio` 片子做完，维护者又说"项目中关于字的节奏也不要写死间隔时间，有的时候太慢"（2026-10-04），于是改成现在的两层：底线只管读一遍（就是 v5 用的那条短标签规则），从容多少交给 Pace 和音乐。补出来的时间里音乐不能停：让配乐"屏息"（鼓撤掉）来配合停留，26 处下来整片像一直在卡顿，加长的小节应当照常往下走（`showcase/04-intro-film` 的 `js/tmap.js`、`tools/retime.py`）。
- 数据图表转场约 1s，分阶段进行（Heer & Robertson 2007）。
- 变形容器里的字（胶囊、卡片在形状之间变形）：容器开始变形约 0.08s 后字再入场，下一次变形开始前约 0.1s 字先退场。字不跟着容器一起拉伸，也不在形状还没稳住时出现。

## 3. 动画原则落到代码

代码写出来的运动显得机械，是因为代码让所有部件同时、沿同一条曲线、以同样幅度运动。对应的修法：

- **预备动作**：大动作前先做一个反向的小动作，比如起跳前下蹲、投掷前后摆、惊讶前先眯眼。它告诉观众往哪看。
- **挤压与拉伸**：撞击和落地时压扁，快速运动时拉长，保持体积大致不变。
- **慢入慢出**：几乎没有东西是匀速运动的，`lerp` 的进度要先过一遍缓动函数。
- **重量**：重的东西起步和停下都慢，落地几乎不弹；轻的东西一下就动起来，会弹，会飘着停下。
- **弧线**：有生命的东西沿弧线运动，不走直线。
- **重叠与跟随**：眼睛先动，身体跟上，手臂、帽子、道具最后停下；每个部件的时间都比它挂靠的部件错开一点。
- **避免对称和同步**：代码会原样复制数值，结果两只手臂角度相同、一群角色同一节奏弹跳。让一只手做主动作、另一只做小动作，错开各角色的相位和种子。
- **夸张**：在短片里，含蓄等于看不见。姿势推到"好像过头了"，再往回收一点。
- **先检查关键姿势**：每个镜头的叙事姿势先当静帧检查，能读懂了再补中间的运动。
- **展示思考过程**：角色先注意到，再想，再行动，而且眼睛先动。

## 4. 排版

- **字体**：一个字体家族用两个字重，层级靠字重和字号区分，不靠换字体。视频里字重对比要拉开，比如 300 对 900。展示字号的字距收紧到 -0.015 ~ -0.05em。不用斜体做强调。
- **可以做动画的属性**：只动画 `transform`、`opacity`、`clip-path`。不要动画 `letter-spacing`、`blur`、`font-weight`，它们会导致重排和跳行。数字计数用 `tabular-nums`。
- **最小字号按"在哪看"定**（BRIEF 的 `Watch on`）。字在屏幕上看起来多大，取决于它占画面多大、画面在屏幕上放多大，和分辨率无关：播放器总是把视频缩放到窗口大小。下表是 1080p 合成里的 px；最后一列是辅助字换到屏幕上大约多大，三档大致对齐：

  | 在哪看 | 画幅 | 看的时候画面多宽（CSS px） | 主标题 | 辅助、标签 | 字幕 | 辅助字在屏幕上 |
  |---|---|---|---|---|---|---|
  | `phone` 手机竖屏 | 1080×1920，或 1:1、4:5、3:4 | 约 360 | ≥ 84 | ≥ 44 | ≥ 65 | 约 15 px |
  | `desktop` 电脑，或手机转成横屏全屏 | 1920×1080 | 电脑播放器默认约 850–1000；手机转成横屏全屏约 640–760（手机比 16:9 长，画面按屏幕高度放） | ≥ 84 | ≥ 44 | ≥ 48 | 约 15–23 px |
  | `feed` 横屏片放在手机信息流里，竖着拿、不转屏 | 1920×1080 | 约 360 | ≥ 150 | ≥ 80 | ≥ 115 | 约 15 px |

  - 竖屏的 hook 文字一般 130–170px，字幕正文 65–95px。
  - `feed` 那一档的字要大得多，因为横屏片在信息流里本来就小。能另出一个竖版（重新构图，不是裁）就另出，比把横屏的字放大到这一档好。
  - **4K**：照常按 1080p 写合成和字号，出片时渲成 4K（HyperFrames `render --resolution 4k`，竖屏 `portrait-4k`，方形 `square-4k`；见 `engines/README.md`），画面和字一起放大一倍，屏幕上看起来一样大。电脑上看 4K，字不需要占画面更大的比例；只有直接按 3840 宽写合成时，表里的 px 才要乘 2。
  - 风格预设的 STYLE.md 里写的字号，是它 5 s 样片用过的数（不少标签是 30–42 px），不是下限；借进片子以后，标题、标签、字幕按这张表来。
  - 来源：`docs/research/06-concept-first-ab.md`（同一个 44 px，竖屏手机上约 15 px，横屏放进信息流只有约 8 px）；屏幕宽度是常见设备的 CSS 宽度【综合】。
- **中文字体**【综合】：思源黑体/Noto Sans CJK 用于正文和字幕，思源宋体用于标题和人文类内容；使用前确认本机已安装，或者把字体文件放进项目的 `assets/`。
- **decode / scramble 字**：字像被程序一点点解码出来，是代码感片子的常用效果。守三条规矩：
  - 乱码由带种子的 `hash(seed, 字符序号, step)` 决定，`step = floor(t / q)`，q 取 1–2 帧。状态只从量化后的时间算，不依赖"上一帧显示了什么"。本仓库的介绍片修过这个坑：同一个 2 帧桶里的状态，曾经取决于先渲染了哪一帧。
  - 每个字符在哪一刻定住，也由 hash 算出。
  - 必读字在 0.3s 内全部定住，read 的停留时间从定住那一刻算起；只当纹理的字可以慢慢解。
- **必读字不要压在屏幕空间的运动模糊下面**：后期运动模糊按镜头速度把整帧抹开，不分前景背景，跟着镜头走的字也会被抹花。必读字在画面上时，把模糊压到 5% 左右；要读长句时不甩镜，改成慢摇（介绍片的做法）。想让快速运动有正确的模糊、同时字不糊，就用真正的亚帧运动模糊：每帧在快门时间内多采几个子帧再平均。相对画面静止的字自然不会糊，而且仍然是 t 的纯函数。做法见 `08-vfx-and-motion-sources.md`。

## 5. 版式与安全区

- **16:9 画面**：1080p 下文字离左右边 ≥ 96px、离上下边 ≥ 54px（EBU R95 的 90% graphics-safe 区）。Remotion 的建议更保守：左右 80px、上下 100px。
- **构图**：主视觉占画面 40–60%。有字幕带时，底部约 17% 留给字幕，居中的主体放在 y≈0.42H。
- **锚点网格**：学 Code2Video，把动画区划成 6×6 格，编号 A1–F6。禁止手写坐标，标签离所指对象不超过一格。
- **竖屏平台遮挡**（第三方给的近似值，发布前用真机截图校准）：

  | 平台 | 遮挡 / 尺寸 |
  |---|---|
  | TikTok | 上约 140、下约 324、右约 170 |
  | Shorts | 下 300–400、右约 120 |
  | 抖音 | 上约 210、下约 340、右约 120 |
  | 视频号 | 竖屏最大 6:7（1080×1260） |
  | 小红书 | 封面 3:4 |

- 【综合】1080×1920 的通用关键内容框：**x 90–900，y 330–1520**。背景可以铺满全屏。
- 4:5（1080×1350）和 3:4（1080×1440）多是信息流里的帖子（Instagram、小红书），平台的界面大多在画面外，不用躲上下两大块，四边各留约 72 px【推测：界面在画面外这一点也没核实；小红书的视频笔记点开后是全屏播放，标题和作者压在画面下方】，发布前用真机截图核对。小红书主页按 3:4 展示封面【二手】。
- **用布局函数，不写死像素**：位置、字号、安全框都由 `layout(W, H)` 按画幅算出，场景代码只引用 `L.title`、`L.safe` 这类命名槽位。时间线（什么时候出现、怎么动）只写一份，16:9、9:16、1:1、4:5、3:4 用同一条时间线各渲一次，再分别看联系表。竖屏不是从横屏里裁一块：`layout` 在竖屏下要重新排，例如左右并排改成上下堆叠。

  ```js
  const layout = (W, H) => {
    const u = Math.min(W, H) / 1080, r = H / W;
    const story = r > 1.6;               // 9:16：全屏播放器，平台界面压在上下和右边
    const post = r > 1.1 && !story;      // 4:5、3:4：信息流里的帖子，界面在画面外
    return {
      safe: story ? { x0: 90 * u, x1: W - 180 * u, y0: 330 * u, y1: H - 400 * u }   // 竖屏关键内容框（见上）
          : post ? { x0: 72 * u, x1: W - 72 * u, y0: 72 * u, y1: H - 72 * u }
                 : { x0: 96 * u, x1: W - 96 * u, y0: 54 * u, y1: H - 54 * u },     // 16:9 与 1:1
      title: { y: story ? 0.30 * H : post ? 0.36 * H : 0.42 * H, size: (story || post ? 130 : 84) * u },
    };
  };
  ```

## 6. 转场

- **方向连续**：A 怎么出去，B 就怎么进来，同轴、同向、同速，并且在运动的中途切。
- **主流向**：全片定一个主流向。其他方向专门用来表达含义：向上表示结论，推进表示深入，拉回表示抵达。
- **种类少、重复用**：每支片子只用 2–3 种转场，反复使用。不用没有承载物的 crossfade（书信体、回忆这类立意里，段落之间经黑场的慢淡入淡出本身就是语言，不叠字，例子见 `cases/oneshot-five.md` 第 2 节）。最好的转场是从内容里长出来的，例如：
  - 跟着动作切（cut on action）；
  - 形状匹配切（match cut）；
  - 镜头运动一路带过去；
  - 画笔擦除；
  - 形状遮罩。
- **暂停测试**：在任意一秒暂停，画面上都应该有有意义的东西正在运动中。刻意安排的停顿除外。
- **镜头内部的变化也是转场**：表情变化要有预备动作，道具沿弧线进出，不要凭空出现。
