### 一句话

一支 **59.7 秒、16:9 1080p30、有配乐**的开场片，用在 README 首屏和 X 发布帖上：
1. 先让人一眼看懂 video-as-code：每一帧都是 f(t)，Opus 5.5 写程序，不画像素；
2. 再用真实界面讲清 OpenVideoHarness 怎么让它每次都靠谱；
3. 放出我们自己的 4 支成片；
4. 最后揭晓"这支片子连配乐都是代码"，落在 `bin/vh` 和 GitHub 地址上。

**静音也能看懂**，因为 X 和 GitHub 都是静音自动播放。打开声音是额外的奖励：每个切点、每次点击都落在拍子上。

### 风格

参考：
1. **`showcase/00-promo-launch-film`**（我们自己的）：延续它的视觉系统。
   - 近黑 #0A0A0B 底，1px 发丝线，6% 蓝图网格；
   - 唯一强调色是琥珀 #FFB224，意思是"harness 此刻在处理的东西"；
   - 转场用向左的 cut-the-curve。
   
   这次在它的基础上加三样：音乐、更大的字、放成片的发丝线窗口。
2. **Ryoji Ikeda《test pattern》系列**：画面和声音出自同一份数据，严格同步。第 1 段的"渲染 click"和第 6 段的"一行代码一轨乐器"借的就是这个。只借同步的纪律，不借高强度频闪：全片任何一秒里，全屏闪烁不超过 3 次。
3. **HyperFrames `sfx-music-launch`**（本地有源码），另外拿 **PDoom** 当节奏标尺。前者示范发布片怎么把拍点交给音乐和音效；后者的标准是每个镜头都有事发生、重音落在拍上。

明确不要：
- "AI 发布预告片"那一套：紫青渐变、光球、玻璃拟态、粒子漩涡、✨ 图标、铬金属 3D logo、预告片式的 braaam 轰鸣。唯一例外是第 3 段的 gag：最多露 6 帧，随后自己盖上 FAIL。
- 功能卡片墙和 PPT：六张等大卡片、要点列表、录屏加推拉。
- 8-bit / chiptune 味的"程序员音乐"，或者随机琶音乱弹。这是代码作曲最容易掉进去的坑。
- 歌词幻灯片式的动态字：每个词同一种入场，从头到尾打字机。

### 引擎

- **只用 HyperFrames（HTML + GSAP）合成。** 项目已经用 `bin/vh new promo intro-film` 初始化，带了 `HYPERFRAMES_SKIP_SKILLS=1`，没有装任何全局 skill。版本上：
  - scaffold 拉到的是 0.8.84，showcase 实测过的是 0.8.82；
  - 开工时先在本地固定 0.8.82，跑一遍 lint 和渲染冒烟测试；0.8.84 没有回归再升级。
- **结构**：root `index.html` 持有音轨、HUD 时间码和颗粒；7 段各是一个 sub-composition。所有时间点都从 `audio/music.beats.json` 和 `audio/events.json` 读取，不手写秒数。
- **showcase 成片怎么合进来**：
  - 四支 `showcase/*/media/final.mp4` 只读，先用 ffmpeg 转成 30 fps、短 GOP、不带音轨的 proxy，放进 `assets/clips/`。01 原片是 24 fps，转 30 fps 时重复帧，不插帧。
  - 在 HyperFrames 里用 muted `<video data-start data-duration data-media-start>` 放进发丝线窗口或铺满全画幅；声音全部由 root 持有。
  - 画面内容不调色、不变速，只缩放、裁切，并在拍点上剪到每支片子最好的瞬间。
  - 02 是竖屏，放在居中的 9:16 窗口里，左侧三分之一放它的标签和题目。
- **真实界面素材**：
  - CLAUDE.md 路由表原文、`templates/REVIEW.md`、`TASTE_CHECKLIST.md`；
  - clawd-leaf 的第一轮和最终联系表，以及 showcase 01 NOTES 里的 FAIL 原句；
  - showcase 02 的 `draw(t)` 代码。
  
  全部拷进 `assets/`，记入素材台账。
- **"这支片子自己的联系表"**（第 1、4、6 段）要渲染两遍：先出 draft，用 `bin/vh sheet` 拼成联系表，存成素材，再出 final。这一步写成脚本（做法和 showcase 00 的 `tools/draft-v1.sh` 一样），保证能复现。
- **p5 手绘引擎和 Manim 都不重新渲染**，它们的产出通过 showcase 01、03 的成片进入。再开一套渲染栈会让接缝处画风打架，还要多花约 1 h，对把事情讲清楚没有帮助。

### 配乐

**推荐：代码作曲。** 分四块：
- **配乐**：`bin/vh music` 读 `audio/score.json`，输出 `music.wav` 和 `music.beats.json`。段落边界就是上面 7 段的边界，冲击点就是各个揭示时刻。
- **音效**：用 `bin/vh sfx place` 摆在画面动作发生的那一帧上，用到 click、typing、whoosh、glitch、error、success、ding、shutter、impact。
- **混音**：`bin/vh mix`，音效出现时音乐自动让位，整体 −14 LUFS。
- **扩展**：4 个"声画同源"的签名时刻超出了共享工具的能力。做法是把 `tools/audio/music.py` 拷进项目再扩展，共享文件不动。

**速度**：112.5 BPM。在 30 fps 下，1 拍 = 16 帧、16 分音符 = 4 帧，所有细分都落在整帧上，卡点误差理论上是 0 帧。换成 120 BPM 的话，16 分音符是 3.75 帧，只能四舍五入。

**音色**：温暖的极简电子，D 小调，不做 chiptune。

| 小节 | 段落 | 音乐 |
|---|---|---|
| 1–2 | Intro | 每格帧被"渲染"出来时响一声 click，音高由帧号决定，所以听到的就是渲染本身。sub bass 渐强 |
| 3–5 | A | half-time 底鼓；代码每流出一个 token 就弹一个 pluck，打字本身就是旋律；pad 垫底 |
| 6–7 | Break | 滤波收紧，军鼓滚奏把 riser 推上去；3 个 gag 各配一下 glitch 顿挫；第 7 小节最后一拍全静 |
| 8–16 | Drop | 4/4 律动全开。<br>• 路由表：8 行对应 8 个八分音符的上行琶音。<br>• 关卡段：每小节最后一拍整轨静音（gate 的本义）；点 ✓ 时响一声 ding，律动在下一拍回来。<br>• 自查段：FAIL 是低频 buzz，PASS 是解决和弦 |
| 17–23 | Chorus | 每支片子一个声音签名：<br>• Clawd：八音盒 pluck。<br>• 傅里叶：加法合成的 lead 每拍多加一个奇次谐波，耳朵里的正弦波一点点变成方波，和画面同步。<br>• 多普勒：lead 随卫星过顶滑音下降。<br>• 00：整个乐队停掉一小节 |
| 24–25 | Breakdown | 只剩 pad。第 25 小节的 4 拍依次进 kick、bass、hats、lead，对应屏幕上依次点亮的 4 行代码 |
| 26–28 | Outro | 第 26 小节强拍是全曲最后一击；打字 tick；余音在 59.4 s 前收干净 |

**卡点规则**：
- 换场落在小节线上；
- 大字和关键 read 落在拍上；
- UI 的小事件（扫行、打勾、打字）落在 16 分音符上。

交付前做一次 cue check：对混音做 onset 检测，和节拍表对比，目标误差 ≤ 1 帧。

**代码作曲和你提供曲目的取舍**：

| | 代码作曲（推荐） | 你提供曲目 |
|---|---|---|
| 切题 | "连配乐都是代码"本身就是片子结尾的揭晓 | 没有这个揭晓，第 6 段要改 |
| 卡点 | 节拍表是写出来的，误差 0 帧；可以做 click 声化、加法合成、关卡停拍 | 靠 `bin/vh beats` 检测节拍，画面按曲子的结构重排；声画同源的几个签名时刻大多做不了 |
| 质感上限 | **风险在这里**：用的是简单的减法合成，可能听起来偏"工程感" | 通常一上来就更丰满 |
| 复现与许可 | score.json 跟项目一起提交，MIT 许可，逐比特可复现 | 需要你确认授权（Suno 等按其条款）；源文件不能放进仓库，别人复现源码时缺音轨 |
| 谁来判断 | 我听不见，只能看频谱、响度和 onset 表 | 同样听不见，但至少曲子是人挑的 |

我听不见声音，这是这个方案最大的风险。所以关卡 ② 会附一段约 20 s 的试听小样（第 8–17 小节，drop 加 chorus 开头），请你先听。如果定稿后想换成你的曲子，也来得及：时间线是数据，按新曲子的节拍重排大约 1 h。

### 旁白 / 字幕（三选一）

| 方案 | 做法 | 好处 | 代价 |
|---|---|---|---|
| **A 纯音乐 + 双语动态字（推荐做主版本）** | 屏幕上一行英文大字加一行中文小字。用 `lang` 变量切换主次，分别渲染 en 主版（README.md、X）和 zh 主版（README.zh-CN.md、B站），再各封装一条 zh/en 软字幕轨 | X 和 GitHub 都是静音自动播放，信息全在画面里；音乐有呼吸空间，卡点最干净；没有 TTS 音色的风险 | 每块字 ≤ 8 个词，至少停一小节，信息密度有上限；"怎么做"主要靠真实界面来讲 |
| B 英文旁白 + 双语字幕 | `bin/vh tts … qwen Ryan en`，再跑 `bin/vh captions` | 能多讲一层细节 | 旗舰片里，本地 TTS 的英文容易听出合成感，科技推特会当成 AI slop；时长由旁白决定（约 65–72 s），拍子要给人声让路；字幕、大字、界面三层文字抢视线；静音播放时照样要烧字幕 |
| C 中文旁白 + 双语字幕 | `bin/vh tts … qwen Serena zh`，再加字幕 | Qwen3-TTS 的中文最好；最适合 B站、小红书、视频号；顺带展示刚加的本地 TTS | 对 X 和英文 README 的观众是门槛；时长约 65–70 s |

- **C 等主版本定稿后，作为"中文旁白版"衍生**。它和主版本用同一条时间线：旁白按小节留好位置，配乐代码按实测旁白长度重排。额外约 1.5 h。
- 如果要试音色：Qwen3-TTS 首次运行要下载约 2 GB 权重，下载前我先问你。

### 费用与时间

- **付费 API：0。** 不用生成式视频、Suno 或云端 TTS。
- **一次性下载**：
  - HyperFrames 的 npm 包（已缓存）；
  - numpy / scipy，进 uv 缓存，几十 MB；
  - 选 B 或 C 时，再加 Qwen3-TTS 约 2 GB。
- **渲染机时（M3 Max）**：
  - draft 每次约 1–2 min，final 每次约 2–4 min。参照：00 是 20 s 的片子，渲了 28 s；02 是 24.8 s，渲了 46 s。本片长约 3 倍，还要解码 4 路视频。
  - 两种语言、GIF 预告和 web 编码，另加约 5–10 min。
  - 全程累计约 30–45 min。配乐合成是秒级。
- **agent 工时**：
  - 关卡 ②（分镜、预览图、20 s 试听小样）约 1.5–2 h；
  - 关卡 ③（音频、7 段搭建、自查）约 4–6 h，第 5、6 段可以派 subagent 并行；
  - 定稿约 1 h。
  
  合计约 6–9 h，主要消耗的是 Claude 额度：上下文长，要读大量图。
- **磁盘**：proxy、draft 和帧缓存约 1–2 GB，随时可以清。
