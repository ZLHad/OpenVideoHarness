**Studio is one window of its own: a click, a command or a sentence brings it up, and nothing about addresses is left to understand**
- Why: opening the console meant understanding addresses and keys, and on the person's machine the address went to a headless Chrome nobody could see. Now the icon, `bin/vh studio` and "打开 Studio" to an agent all do the same thing: the window appears, or comes to the front when it is open already, and there is never a second one.
- The window: the console starts a Chromium-family browser it names outright (Chrome, Chromium, Edge or Brave; never a headless one, never "whatever the system calls the default browser") with Studio's own profile under `~/.cache/ovh/studio-window/` and `--app` (no address bar, no tabs, no extensions, nobody's session). It counts as open only when its page connects back (a presence stream); else the console closes it and tries once more, then a tab of the default browser, and says which. With none of those browsers it opens in a tab, and says so. Open already: macOS brings that very window to the front (by its process), Linux does with `wmctrl` or `xdotool` when there. Two clicks or two terminals at once still give one window. The window is made in one file, `tools/desk/window.py`, so a desktop shell can replace it later. Closing the window leaves the console running (an agent may be at work); the console's end closes its window.
- Access without anything to read: the window's address carries a one-time code that lives a minute; the page's script trades it for the run's token (`POST /api/claim`), so the code still visible in the browser's command line opens nothing. A GET of the page gives and changes nothing, however often it is fetched. Nothing printed or written holds a way in (`bin/vh desk`, `studio`, `gate`, `--json`, logs, `.desk.json`); this withdraws the printed address of `changes/desk-key-reusable.md`. `POST /api/open` shows the window, needs nothing, answers only whether it did (twenty a minute). A page that can only look says "这一页现在只能看。" with one button, "在 Studio 窗口里打开"; Studio's own window whose access lapsed (the console restarted) is replaced by a fresh one by itself. `--print-address` (a browser on another computer) prints an address that opens one page, once, within ten minutes.
- `bin/vh studio [<project>]` (`tools/desk/studio.py`): the console started in the background when it does not run (it stops 12 h after its window closes), its window raised or made, on that film when one is named; a film outside Studio's folders opens in its own desk. `bin/vh desk` in a terminal shows the window too. `bin/vh gate … --desk` shows the stop in Studio's window when Studio runs and has the film, else in the project's own desk; its message says the stop is open in Studio's window, with no address, or what to run when the window did not open. The page's title is Studio.
- `bin/vh studio --install-icon [--dir DIR]` makes the launcher: on macOS `~/Applications/OVH Studio.app`, a stay-open AppleScript applet (click again: the window to the front; quit it from the Dock: the console it started stops and its window closes, asking first while an agent is mid-turn; when the console stops by itself the icon quits too); on Linux a desktop entry. It runs `bin/vh studio` in this clone, so a `git pull` needs no reinstall, and a clone that moved says which command to run again. Made on the machine with what it has (`osacompile`, `codesign`, stdlib Python), ad-hoc signed, never quarantined, so Gatekeeper does not stop it; a copy on another machine will not work there. `--remove-icon`, `--icon-status`; `bin/vh doctor` has a `studio-icon` line. The Dock shows the browser's icon for the window itself; a window with Studio's own Dock icon needs a desktop shell, a later step.
- The picture is drawn by `tools/desk/icon.py` (no Pillow, no SVG renderer): the console's dark ground and cyan square with a viewfinder's four corners, the square alone at 16 and 32 px. The PNGs and `.icns` are made at install time, not committed; the three designs considered are in `docs/assets/studio-icon-designs.png`.
- `install.sh` asks once whether to install the icon (only with a person at a terminal, also under `curl | bash`; `--icon`, `--no-icon`), and the end of its message lists the three ways to bring up Studio. `tools/changes.py release` makes the icon in a temp folder first and refuses while it cannot; the READMEs say how to open Studio.
- Checks: a new `studio_checks` group (one window from an agent and from a terminal, two at once, after the window closed and after its console was killed; a page that never connects, then a tab; no browser; neither; no secret in any output or file; a film outside Studio's folders; `--print-address`; the icon's open/alive/quit; the Linux entry and the macOS app made, refused over another's file, removed, a moved clone, doctor's line, the picture, install.sh's question, the release's check). `agent_checks`: the attacker also reads the process list (the window's code is there) and tries every string as a code and a token, and calls `/api/open`; the door's checks follow the window (a GET gives nothing, a code works once and expires, the next stop raises the window, `desk link`, `gate --print-address`). `tools/ci.sh` sets a stand-in window (`tools/desk/fixtures/studio_window.py`) and profile folder for the whole run, so a run opens no window and never touches the person's own.
