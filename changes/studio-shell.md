**OVH Studio: Studio's own window, with its own frame, Dock icon and menu (an Electron shell around the same page)**
- Why: the browser window that showed Studio still wore the system's title bar and a browser's Dock icon. Studio now has a window of its own; the page in it is the same one a browser shows, so there is still one Studio to build and test.
- `bin/vh studio --install-icon` makes `OVH Studio.app` (Linux: a desktop entry): Electron 45.2.3 from a committed lockfile (`tools/desk/shell/`, every package from registry.npmjs.org with its integrity hash, no install scripts), its binary checked against the checksums in that package and kept in the cache (about 130 MB downloaded once, about 254 MB on disk; a reinstall works offline; with `--dir`, the download, the record and everything made go inside that folder), renamed to OVH Studio with its own bundle id and icon, its code a small boot that runs the shell from this clone (a `git pull` needs no reinstall; a moved clone says which command to run), signed ad hoc. `--no-shell`, or no npm and nothing cached: the small launcher of before, said so. `install.sh` asks once and names the size; `bin/vh doctor` has an `electron` line; `tools/modules.json` lists it.
- The window: no system title bar; on a Mac the three buttons sit in the page's own top bar, placed for each theme, and the bar is what the window is dragged by; the window takes the theme's colour before the first paint and shows when ready (no white flash); full screen gives the bar its room back. Linux draws its buttons over the bar's right end. A menu in Chinese or English (following the system), with Close Window (⌘W); the player's full screen works (allowed for the console's own page only); a link to another page of the same console (the static gate page, a transcript, an enlarged image, an attached video, sound or other file) opens in a reader window of the app's own: the console's reader page (`GET /v/<key>/<path>`: text and markdown as text, a picture, a player, a page in a frame, else a sentence saying where the file is), no system title bar, the theme's ground and a slim bar to drag by with the buttons in it, the file's name as the window's, ⌘W closes it, and it goes with the window that opened it; links to other sites go to the default browser, other local addresses nowhere; one Dock icon.
- One app, one window a desk: the console starts it with one line on stdin (the window's address with its one-time code; nothing on its command line), and a second start hands its line to the running one through Electron's single-instance lock, which raises its window itself. The app trades the code itself and keeps the console's token in its memory alone, tied to the window it was traded for, and adds it only to that window's own page's requests to that same console; the page holds a placeholder, so the token is in no command line, page, storage or file. Any local program can hand the app a line: no authentication for that, but a window whose console still answers with the app's token is never pointed at another console. These decisions live in `tools/desk/shell/rules.js`, checked under plain node. Hardened: isolated, no Node, sandboxed, no webview, the console's own pages only, no permissions; the preload gives the page `ovhShell.platform`, `ovhShell.access` and `ovhShell.theme()` alone, and the page takes the frame only when it sees them.
- One Studio: a film outside Studio's folders (`bin/vh studio <film>`, or `bin/vh gate` while Studio runs) joins Studio's space and opens in its one window, not in a desk and window of its own; the last fifty such films are listed beside the console's own file and survive a restart.
- The console tries Studio's own window first, then a browser's window (#213), then a tab, and says which; an app that is gone or broken is noticed in about a second. A clone that moved: started by the console, the app exits at once with no alert and the console says to ask the agent to put the icon back; clicked, one alert, with "Find it…" to pick the folder OpenVideoHarness is in now (its `bin/vh studio --install-icon` makes the app again and opens Studio). `--remove-icon` quits the running app first; a default removal also takes the download cache and the app's own profile when they are its own, and says what it left. Closing the window leaves the console running; quitting OVH Studio stops the console it started (asked first while an agent is mid-turn); the console's end closes its window.
- The stage row in the top bar starts at its first stop when the bar is too narrow (it was cut off at the front in a browser too).
- Checks: a stand-in app (`tools/desk/fixtures/studio_shell.py`) for the window's behaviour; the app made from a stand-in Electron folder (name, bundle id, icon, boot, signature, the record the console finds it by; Linux too); the shell's source pins and hardening; no check downloads Electron or touches the app installed on the machine.
