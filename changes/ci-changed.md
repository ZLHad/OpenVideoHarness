**`tools/ci.sh --changed` runs only the groups a change needs, and a narrow line of its table has to be shown to be enough**
- Why: a full run takes 15–18 minutes on CI's macOS and about 10 on a fast Mac, and the parallel sessions ran it two or three times each while they worked. `OVH_CI_SHARDS=<table>` could run some groups, but you had to write the table, and a partial table turned one of doc_checks' checks red ("never run").
- `tools/ci.sh --changed [base]` compares with base (`origin/main` by default), working tree and new files included, and runs the groups `tools/ci-paths.txt` names for the changed paths. A path the table does not know runs every group. Syntax, docs and the read-path table run every time.
- A narrow line needs a reason, and `python3 tools/ci_select.py --check` is it: from each file a line matches it follows what imports it or names it in code, and on to what imports or names those; then the `bin/vh` commands that name any of them and the groups that run those commands, and the groups of `tools/ci.sh` that name any of them. A line that misses one of those groups, or reaches every group, fails. `--suggest` prints what each line must name.
- So most paths run everything for now: `bin/vh`, the engines, the templates, `CLAUDE.md`, `playbook/` and `video-types/`, the styles and components, and the shared tools (status, review, the desk, jsonerr and what they use) reach nearly every group. What saves time is a change at the edges: the change notes, landing and these tools, a few tools one or two groups use, pages for people.
- The check cannot see a tool that runs another through a name it builds (`tools/film/$tool.mjs` in `bin/vh`) or through `bin/vh <command>` from inside Python, nor a file read by a path that never spells its name.
- A change to `tools/ci.sh` runs the group whose function it is in; a helper runs the groups that call it; a comment above a function counts as that function; the top and the dispatch run everything. bash itself says where each function starts (macOS's bash 3.2 names a line further down for a function with a heredoc in it; the line that defines it is found from there, and the check runs under both). A group added to `tools/ci-shards.txt` runs. Paths are read NUL-separated, so a name with a space or Chinese in it is matched as it is.
- `python3 tools/ci_select.py --why` says what each changed path runs and why, without running anything.
- A run of some groups (a shard, `--smoke`, `--changed`, another table) ends with "Ran N of the M groups", and doc_checks reads `tools/ci-shards.txt` itself, so a partial run is no longer a broken table.
- The full run before a push stays the rule (`CONTRIBUTING.md`); CI on a PR still runs everything.
