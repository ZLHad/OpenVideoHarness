**Studio polish 1: the checks keep away from your own Studio, the cut player has sound controls, the agent column installs an adapter on a click, the installer asks nothing, the space says what this computer lacks, and the model and effort are a plain choice (Claude Code starts at Opus 5.5, xhigh)**
- Why: with a person's Studio running, check runs found it and joined their temporary films to it; most draft films have no sound and Studio played them without a word, so they looked broken; setting up an agent meant copying a line into a terminal; the installer asked a question a first-time person could not answer; and nothing in Studio said when a tool it needs was missing.
- The checks: `tools/ci.sh` gives each run a temp folder of its own (`$TMPDIR`, removed at the end) and each group that starts desks, Studio, gates or the agent column a temp folder inside it; the person's projects (`$OVH_PROJECTS`) and installed agent adapters stay out. A decoy "running Studio" stands where any other group would find one, and the run checks it was left byte for byte as it was, nothing joined to it and nothing asked of it. `tools/desk/test_agents.py` takes a temp folder of its own too, run alone or under `tools/ci.sh`.
- The cut player: a mute button and a volume slider next to the time, remembered by the browser; a film with no sound track says "这一版没有声音" / "This cut has no sound" in the line above the picture, and its sound controls are off. When the stop names no film and the one `bin/vh status` picks has no sound, Studio plays a cut that has (the storyboard's animatic, a gate page's film or animatic); `bin/vh status` itself is unchanged. ffprobe looks once a file, as long as its size and time stay the same.
- The agent column: "装上" / "Set it up" installs the adapter itself (`bin/vh desk agents install <kind>` in the background, with the page's access like any other action), shows how long it has been going, and switches to the conversation once it is ready; a failure says why in one sentence (no Node, most likely the network) and only then shows the command to copy.
- `install.sh`: no question. On macOS and on a Linux desktop it puts OVH Studio in the applications, saying so in one line with the size; `--no-icon` leaves it out (`--icon` is still accepted). A missing tool, a failed download or a step that did not finish says what to do next in one sentence, and the last lines are the two ways to start: click OVH Studio, or open Claude Code or Codex in the folder and say what film you want.
- The space: when this computer lacks something a film needs (FFmpeg, Node, uv, git, a browser to draw pages with, an agent for the column; from `bin/vh doctor`, asked once a run), one quiet panel says what is missing, what it stops, and the one thing to do. Nothing when all is there.
- Model and effort: the agent column's head has a model menu and an effort menu (the mode and the rest fold behind one button), and where a conversation starts it says what it will start with, as menus once this run has seen the agent's list. A new Claude Code conversation starts at Opus 5.5 with effort xhigh when the agent offers them, else its own default; Codex and DeepSeek Harness keep theirs. What the person picks is remembered on this machine for that kind of agent (`picks.json` beside the installed adapters, never in a project) and is where the next new conversation starts; a running conversation is never changed behind their back, and only values the agent itself reports are ever sent. The highest effort uses more of the person's plan; the effort menu lowers it.
