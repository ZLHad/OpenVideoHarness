**A new project reads the taste checklist from templates/, a gate goes on record in REVIEW.md alone, and a concept card has a place for its frame, titles and cover**
- Why: after #206 a dry-run agent and a review found what still made an agent write or read a thing twice: every project kept its own copy of `templates/TASTE_CHECKLIST.md`, and gate ① was on record only once REVIEW.md had the person's words and the decision and DECISIONS.md said the same concept again. They also found what an agent could not do from the docs: draw a concept card's frame before there is a composition, put the two titles and the cover a knowledge short's card carries anywhere but `pro`, know when to read the text-size floor it writes into the BRIEF, or make a short with no network.
- `bin/vh new` no longer copies `TASTE_CHECKLIST.md` into a project: the self-check and the reviewer read `templates/TASTE_CHECKLIST.md`, and a film that leaves one of its items aside says which and why in its own `DECISIONS.md` (the checklist's head, playbook/12 §6). A project that already has a copy reads its own, as before; `tools/artifacts.json` keeps the file as optional. playbook/01's project tree, CLAUDE.md's directory line, playbook/02's reviewer brief and the quick card say so.
- Gate ①'s record is REVIEW.md's alone: the person's words and "定了：…" under 关卡 ①. `bin/vh render` and `bin/vh check` no longer refuse a film whose DECISIONS.md concept row is still 待定; every other refusal stays (no words, no decision, a decision still 待定, the template's 定了：{…}, a waiver under gate ③ only, gate ② for a film whose plan has it), and `tools/ci.sh` now has one check for each. `bin/vh status --json` gives the concept from REVIEW.md (`record.concept`, `concept_from`; an older project's DECISIONS.md row still counts). The DECISIONS.md template's concept row asks only who decides.
- A concept card's frame before there is a composition: a one-page sketch in `out/review/` that sets `window.film`, and `bin/vh frames <page> --at 0` (playbook/12 §7). A knowledge short's gate ① skeleton asks each card for its two titles and its cover layout (`titles`, `cover`), and the static review page shows them on the card (the console's cards do not yet). playbook/10 §1's first step says one rule: a hook on each concept card, three hook cards of different kinds only with `hook=own`.
- `bin/vh status` lists playbook/03 §4 (the text-size floors) at the stop where the BRIEF is filled: gate ①, and a quick film's first step. The GitHub release and README clip limits move from playbook/01's 规格 to CONTRIBUTING.md.
- `bin/vh new --no-install`: a project with no network now: HyperFrames' init and the hand-drawn engine's npm install are left out, the command that installs the engine later is said, exit 0 (`--json`: `scaffold.skipped`). `bin/vh status` lets gate ①'s work go on without the engine (that command comes last) and asks for it first before the scenes, as it did; a scaffold that failed offline is read the same way.
- CLAUDE.md's 努力程度: "只说"不用审、直接出"或"中间我不看"、而没提档位的，也按 quick" (a dry-run agent read the old wording as "any request that names no level is quick"; 停在哪 already said it so). DECISIONS.md's head says a concept the agent decides (quick) goes there, one the person decides at gate ① in REVIEW.md. playbook/12 §7's sketch commands write `<项目>/` in front of their paths.
- CONTRIBUTING.md: several sessions run the checks on one machine at once: stop your own run by the PID you noted, never `pkill -f`, and leave other runs' `vh-ci.*` folders alone.
