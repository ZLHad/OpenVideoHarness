# 案例：五支社区代码视频，立意先于风格（2026-09-29 至 10-01）

五支片子分别是一支知识科普、一支写给用户本人的肖像片、一支自我介绍式的动效片、一支公司 showreel、一支产品发布片。类型各不相同，共同点是：每一支都先有一个"立意装置"，也就是一个让形式本身就在讲内容的点子，从成片看，风格都在服务这个点子。两支公开了 prompt（第 2、3 支），都只有几句话：第 2 支的标题说是"一次直出"，第 3 支的作者在片头口播里说是"用一句话"生成的；FunTech 那支做了三天。

**怎么拆的**：2026-10-01 在内置浏览器里播放原片，把 `<video>` 跳到指定时刻，画到 canvas 上拼成联系表再截图（`playbook/07-reverse-engineer.md` 的不下载做法）。每支按 1.5–8 s 一帧取样，共约 170 帧；字幕和 HUD 读数靠局部放大来读。声音用 WebAudio 量每 50 ms 的电平（第 1、4 支），只能看出响度起伏，听不出内容；第 5 支的声音没有量。没有下载原片，下文不附原片画面。取样稀疏，切点前后没有逐帧看，所以下文关于转场、缓动、"多久没有变化"的判断只是线索。

**许可**：原片和 prompt 都归各自作者。下文是转述和分析，引文都很短；作者公开的 prompt 只转述大意，原文见链接。

## 1. 你问 AI 一句话之后的 3 秒钟

**类型**：16:9 横屏科普，2 分 6 秒，中文屏幕字幕。
**来源**：[抖音](https://v.douyin.com/MONt8dOfuEo/)，科了个喵，2026-09-29 发布。到 10-01，4.6 万赞、1.2 万收藏、1.5 万转发、1368 条评论，账号本身只有 1853 个粉丝。页面标注"内容由 AI 生成"。
**源码和 prompt**：未公开。评论里有人说美术和配乐是用 WebGL 和 WebAudio 写出来的，作者没有确认。

### 画面拆解

| 时间 | 画面 | 手法（【推测】为推断） |
|---|---|---|
| 0–5 s | 浅色聊天输入框里逐字打出"天空为什么是蓝色的？" | 仿真 UI，打字机 |
| 8–14 s | 大字"回车之后的 3"，再变成"3 秒"和一圈计时环，读数 0.000 s；字幕说要把这 3 秒放慢来看 | 开场就交代装置 |
| 16–24 s | 问题被装进 HTTP 请求，再被 TLS 加密成乱码；设备 → 路由器 → 运营商网络的节点图 | 顶部 HUD 从这里开始常驻 |
| 28–36 s | 数据包穿过骨干网，点阵地球上一条弧线从"你"连到"数据中心" | 【推测】Three.js 或 canvas 点阵球 |
| 40–44 s | 三道拱门：解密、验证身份、检查请求；调度器把请求分给空闲 GPU | 横向流程，镜头推近到调度器 |
| 46–61 s | 问题接在系统提示和历史对话后面；拆成 7 个彩色 token，各带编号；每个编号展开成一串数字（向量）；落进"意义空间"的散点图，和意思相近的词挨在一起 | 每个 token 有自己的颜色，后面所有场景都沿用 |
| 64–76 s | 进入 Transformer：7 根彩色柱子穿过几十层；每层每个 token 回看前面的 token（弧线），层数读数走到第 80 层 | 【推测】伪 3D 层叠 |
| 79–88 s | 模型太大，拆到 8 块 GPU 上；每个 token 约 2000 亿次运算；最后给词表里每个词打分，概率条形图 | 数字有量级，没有给出处 |
| 91–94 s | 一圈放射线中间诞生第一个 token"因为" | 全片的小高潮 |
| 97–112 s | KV 缓存表一行行填满，答案逐个 token 流回聊天框 | 慢放倍数一路降：×22、×13、×7、×5 |
| 115–118 s | 读数停在 3.000 s，慢放显示"暂停"；背景变成蓝天、太阳和云，三个读数卡片：0.08 秒到数据中心、0.45 秒出第一个 token、3 秒答完 | 答案"天空是蓝的"变成了画面本身 |
| 122–126 s | 片名"回车之后的 3 秒"在蓝天上淡回 | 首尾呼应 |

**HUD 是这支片子的骨架**。顶部一直挂着三样东西：左边是带编号的阶段标签（例如 01 打包·加密、05 变成向量、09 逐个生成），中间是"回车后 x.xxx s"，右边是"慢放 ×N"。实测的读数：

| 屏幕时间 | 真实时间 | 慢放 | 讲的是 |
|---|---|---|---|
| 16–24 s | 0.001–0.004 s | ×2,500 | 打包、加密、出门 |
| 28–44 s | 0.029–0.239 s | ×160 → ×50 | 跨洋、进数据中心、调度 |
| 46–61 s | 0.240–0.244 s | ×10,000 → ×2,000 | 拼上下文、切 token、变向量 |
| 64–94 s | 0.270–0.452 s | ×80 → ×2,200 | Transformer、多 GPU、打分、选出第一个词 |
| 97–112 s | 0.543–2.617 s | ×22 → ×5 | 逐个生成 |
| 115 s | 3.000 s | 暂停 | 答完 |

46–61 s 那一段（拼上下文、切 token、变向量）真实只占 0.004 秒，屏幕给了 15 秒；逐字生成（0.45 → 3.0 秒）真实占 2.5 秒，屏幕给的也只是 20 秒上下。屏幕时间是按"需要讲多少"分的，不是按真实时长分的。慢放倍数把这个取舍明明白白写在画面上，观众不会觉得被骗，反而多了一条信息：哪一步快得离谱。

**视觉系统**：
- 浅色：薰衣草、桃、薄荷三色的柔和渐变底；
- 白色圆角卡片，阴影很轻；数据和 HTTP 报文用等宽字；
- UI 只有一个蓝紫强调色，7 个 token 各有一个颜色，从切词一路带到 Transformer 和输出；
- 字幕在底部居中，关键词换成强调色。

**声音**：评论区有人提到背景音乐，【推测】全程有配乐。电平的起伏和章节对应：开场约 −22 dB，网络传输一段约 −16，GPU 运算一段约 −14，84–88 s 掉到约 −24（第一个 token 选出之前），之后回到 −14，收尾约 −19。每 2 s 窗口里 50 ms 电平的波动只有 1–1.5 dB，有人声旁白的话起伏会大得多，所以【推测】没有配音，屏幕字幕就是全部文字。

### 为什么有效

1. **题目自带装置**："3 秒钟"给了一个可以量、可以放慢的东西。慢放让一个抽象流程有了时间轴，观众随时知道"走到哪了、还剩多少"，2 分钟不嫌长。
2. **一个主体贯穿**：7 个彩色 token 从输入框一路走到输出，抽象的"向量""注意力"都落在同一组看得见的东西上。
3. **结尾把答案变成画面**：问的是"天空为什么是蓝的"，答完那一刻背景就是蓝天；片名"回车之后的 3 秒"在蓝天上淡回，和开场呼应。
4. **问题选得好**：人人都问过 AI，"回车之后发生了什么"是一个没人细想过、但一说就想知道的问题。

### 用本仓库复刻

- 类型：`video-types/02-knowledge-short.md`，横屏中长版；讲机制的段落借 `01-math-science-explainer.md`。
- 引擎：HyperFrames。HUD 是一个常驻组件，读数由一张"屏幕时间 → 真实时间"的分段映射表算出来，慢放倍数是这张表斜率的倒数。
- 可以套用的题目：任何"X 发生的那一瞬间"，例如刷卡支付的 2 秒、按下快门的 1/125 秒、一次心跳、一次 DNS 查询。分镜时先写映射表，再按 reads 分屏幕时间。
- 事实：每个读数（0.08 s 到数据中心、每 token 的运算量）要写进 NOTES.md 并给出量级依据，这支原片没有给出处。

## 2. 我眼中的你

**类型**：16:9 横屏，3 分 51 秒，TTS 旁白加同步字幕。
**来源**：[抖音](https://v.douyin.com/kTpIVOEMsEY/)，陈与小金。10-01 时 685 赞、220 收藏、205 转发。
**作者说了什么**：标题说这是 Opus 5.5 读完他所有对话后"一次直出"的。标题里公开了 prompt，大意是：根据你对我的全部记忆、文档、仓库，以及 Obsidian 里的个人档案，做一条"在你眼里我是什么样的人"的视频；时长、画面、声音、配乐、音效都由你定，技术随便用，缺库自己装。评论区有人问是不是给了图片和音频素材，作者回答"都没有"；有人问 TTS 用的是哪家，作者说不知道。

### 画面拆解

| 时间 | 画面 | 旁白大意 |
|---|---|---|
| 0–10 s | 暖黑底的终端，光标闪；打出用户自己说过的一句话（嫌 Claude 对他了解不够）；Claude 的橙色星标在转 | 冷开场用用户原话 |
| 10–30 s | 文件名一行行滚过（日记、memory 文件）；四个计数器跳出来：212 篇日记、194 条记忆、8,472 句对我说的话、1,434 次提交 | "每次新的对话开始，我都不记得你"，所以你把自己写进了文件 |
| 36 s | 片名"我眼中的你"，旁边是一张由文字组成的人像 | 【推测】从资料库里找到照片，转成字符画 |
| 42–60 s | 一条时间轴，节点是带日期的用户原话；第一次 git 提交的哈希和信息 | 第二天，你有了第一次提交 |
| 66–90 s | 被划掉的账号卡片（账号被封）；"快坚持不下去了"那天的日记；30 万播放的数字；154 天的打卡格子只空了 3 天 | 三天后你发的视频播了三十万；154 天里只有三天没来 |
| 98–106 s | 毛笔感的大字，是用户最常说的口头禅；满屏的文字墙 | 你问过我多少次为什么、说过多少次不对、说过几次谢谢 |
| 114–122 s | 夜里的城市，只有一扇窗亮着 | 一半的日子你过了十一点半才停 |
| 130–146 s | 争执时的聊天气泡，原样放出 | 每一次，你都没有换掉我 |
| 154–162 s | 1,055 / 1,434 次提交，旁边是 Co-Authored-By 的署名行；像素城市一块块垒起来 | 你的提交里有一千多次写着我的名字 |
| 170–186 s | 用户反思自己"开始不思考、更易怒"的原话；星标回一句"同意" | 不回避摩擦 |
| 194–214 s | 人像回来，右侧一块标着【推断】：先引用户的一句原话（他的签名档"祝你 token 无限 永远自由"；画面里这句带着一个错字，【推测】是原样照抄），下面一行灰色小字注明出处"对话 / 日期 时间"，再写 Claude 从中推出的一句判断；人像散成粒子 | 这次对话结束，我又会忘记这些 |
| 219–231 s | "祝你身体健康，永远平安"，下一行把用户自己的那句祝福还给他；片名和署名 | 首尾呼应 |

**视觉系统**：暖黑底（不是纯黑），中文宋体，暖白和淡金两种字色；日期、文件名、哈希用等宽字；旁白字幕以 Claude 的橙色星标开头，逐字打出。镜头很慢，从 8 s 一帧的取样看，一个画面常停 6–15 秒；段落之间从黑场慢慢淡入。

### 为什么有效

1. **材料足够具体**：全片几乎每一句都有一个只属于这个人的数字或原话。具体到这个程度，观众即使不认识他也会被打动。
2. **视角是装置**："AI 每次都会忘记你"这个事实被做成了首尾：开头"我都不记得你，所以你把自己写进文件"，结尾"对话结束，我又会忘记"。机器视角本身就是情绪来源。
3. **不只说好话**：账号被封、半夜不睡、吵架、对 AI 依赖的担心都在片子里。有摩擦，赞美才可信。
4. **证据和推断分开摆**：原话照抄，下面注明哪次对话、几点几分；Claude 自己的判断单独标【推断】。这是我们"事实照抄原文"那条纪律，被做成了画面语言，反而增加了可信和亲密感。
5. **最后把用户自己的话还给他**：签名档里那句祝福，在片尾成了 Claude 对他的祝福。

### 用本仓库复刻

- 本仓库没有对应的类型。最接近的是 `video-types/05-data-story.md`（数据驱动）加 `playbook/09-narrative.md`（长片叙事），旁白按 `playbook/04-audio.md`。
- 关键在素材挖掘：先把材料里的数字（篇数、次数、天数、时间分布）和原话列成表，再写稿。每个数字照实写进 NOTES.md，可以复算。
- 隐私：材料是私人记录，成片要公开时，先把会出现在画面里的原话、截图、人像列给本人确认。
- 适合的题材：年度回顾、项目周年、给团队或家人的片子、"这个仓库眼里的我"。

## 3. Opus 5.5 自我介绍：用做法讲做法

**类型**：16:9 横屏，34.7 s，前 5 s 是作者本人出镜口播，后约 30 s 是生成的片子；配音加字幕（prompt 要求女声；评论区有人问 TTS 用的哪家）。
**来源**：[抖音](https://v.douyin.com/bGfv-xMIKWc/)，云野FLOW，2026-10-01 发布，prompt 注明来自 @光郡。
**作者说了什么**：片头口播说这是用一句话让 Opus 5.5 生成的视频。标题里公开了 prompt，大意是：做一段 30 秒、二维加三维的动态图形，展示动效设计的实力，其余都由模型定，技术随便用。三条硬要求：**不要调用电脑上配置的任何 skill**；配音里要有一段女声自述，以"我是 Opus 5.5"开头，讲这支视频是怎么做的，让小白听懂；缺什么自己补。评论区有人说声音生成不了，作者回复：让它自己想办法，装一个能生成声音的模型。

### 画面拆解（生成部分）

| 时间 | 画面 | 旁白大意 |
|---|---|---|
| 6–9 s | 粒子聚成"OPUS 5.5"，四周飞过线框方块 | 我是 Opus 5.5，你看到的每一帧都是我做的 |
| 10–12 s | 黑屏上一根光标；代码墙上叠着大字"代码" | 没有摄像机，只有代码 |
| 13–15 s | 时间轴编辑器，一个橙色小球按时间轴飞 | 先写剧本：谁几秒出场，往哪飞 |
| 16.5 s | 2D 画布上的几何图形、花纹、圆环 | 平面的，在画布上一笔笔画 |
| 18–21 s | 线框球体变成有光影的球，再到一个带网格地面的 3D 场景 | 立体的，用 Three.js 搭一个摄影棚 |
| 23 s | 着色器算出来的流体玻璃团 | 光和颜色交给着色器 |
| 25 s | 屏幕上写着正弦公式，波形随之起伏 | 音乐音效全是数学算出来的声波 |
| 27–30 s | 满屏缩略帧，计数器跳到 0937；然后一条胶片带，1800 帧 | 最后把一千八百帧一张张拍下来，拼成这三十秒 |
| 32 s | logo 和一句"每一帧，都是算的" | 想做点什么？随时叫我 |

**视觉系统**：黑底，一个橙红强调色，四角有等宽字的小读数，字幕里的关键词换成强调色。旁白说 1800 帧拼成 30 秒，若如此是 60 fps。

### 为什么有效

1. **形式就是内容**：讲"用 Three.js 搭摄影棚"时，画面就是 Three.js 的场景；讲"声音是算出来的"时，画面就是那条公式的波形。观众看到的就是证据。
2. **结构现成**：制作流程本身有先后（剧本 → 2D → 3D → 着色器 → 声音 → 渲染），不用另外编故事。
3. **首尾呼应**：开头"你看到的每一帧都是我做的"，结尾落在"每一帧，都是算的"。
4. **prompt 只给了角色、篇幅、必须说的一句话和完全的技术自由**，还明确不让它用预设的 skill。本仓库本身就是一套 skill 和规则，这一条值得记着：给模型的东西，是在帮它还是在框它。

### 用本仓库复刻

- 类型：`video-types/03-product-promo.md` 或 `08-brutalist-meme.md` 的节奏。
- 这个结构可以用来讲任何"怎么做的"：一个工具、一条流水线、本仓库自己（showcase 00 的 beat 03 展示草稿和修复，是同一个思路的一小段）。
- 按 TASTE_CHECKLIST #20，四角读数通常算通用 AI 装饰；原片里这些读数是否随讲解变化，没有逐帧核对。

## 4. FunTech Showreel 2026

**类型**：16:9 横屏，49.7 s，【推测】只有配乐和音效，没有人声。
**来源**：[X](https://x.com/tkm_hmng8/status/2105255710531674358)，ハシモトタクマ（FunTech 的设计师），2026-09-30 发布。10-01 时 37.5 万浏览、2058 赞、1807 收藏。
**作者说了什么**：用 Opus 5.5 做视频，"看你怎么下功夫，能做到这个程度"，制作周期 3 天。回复区要登录才能看，没有读到更多做法。

### 画面拆解（约每 2 s 一帧，几乎每帧都是新镜头）

| 时间 | 画面 |
|---|---|
| 0–2 s | 绿色终端打出 BOOT；接着一段酸性黄的数据损坏画面 |
| 4–8 s | 铬面头盔吉祥物（绿色像素眼、橙色鞋）站在黄蓝波纹字背景前；充气铬字 logo；面罩倒影特写 |
| 10–12 s | 贴纸轰炸（笑脸、片假名贴纸）；一个夸张的讽刺漫画人物站在巨大的红字前 |
| 14–22 s | 美术馆里：运动模糊的真人、铬面雕像、一群青铜雕像，字幕"WE ARE FUNTECH"，聚光灯和闪光 |
| 24–26 s | 霓虹东京小巷，吉祥物站在发光圆环里 |
| 28–30 s | 瑞士海报版式"FUNTECH SHOWREEL 2026"，CRT 显示器里是吉祥物；屏幕碎裂，漫画拟声字 |
| 32–42 s | 黑白网点漫画分格；绿色线框"HELLO WORLD"；Win95 桌面；蒸汽波游戏关卡"WORLD 1-3"；漫画"ERROR"；VHS 的"NO SIGNAL" |
| 44–46 s | 画面碎成白底上的碎片 |
| 47–50 s | 白底上的黑色充气铬字 logo 和吉祥物 |

**声音**：【推测】全程是密集的配乐，约 −16 dB。23 s 处短暂收住（随后切进霓虹小巷），27–30 s 一段放轻，**43–45 s 有约 1 s 的真静音**（电平降到 −65 dB 上下，其中有数字零），和碎成白底那一下几乎同时，然后是终场 logo 和淡出。

**手法推测**：吉祥物在十几种风格里形象一致，【推测】是公司已有的 3D 角色资产，或者先用图像模型定好形象再参考生成；美术馆真人和青铜群像【推测】来自生成式视频或图像模型，再用代码合成 UI、字和转场。3 天的周期说明不是一次直出。

### 为什么有效

1. **混搭有锚点**：每 2 秒换一个世界，但吉祥物、FUNTECH 字标、游戏式 HUD（关卡号、分数）一直都在。观众知道看的是同一个主角。
2. **混搭本身就是信息**：创意公司的 showreel 要证明的就是"什么风格都能做"。
3. **终场前的静音**：密集了 43 秒之后突然一秒全静，碎屏转白，再落 logo。
4. **首尾呼应**：4–8 s 的充气铬字 logo，在片尾换成白底黑铬再出现一次。

### 用本仓库复刻

- 类型：`video-types/03-product-promo.md`（品牌片），节奏借 `08-brutalist-meme.md`。
- 本仓库的风格库正好可以这样用：一个吉祥物或一个字标，依次穿过 6–10 个预设世界，每个 2–4 s；[`styles-gallery.mp4`](https://github.com/ZLHad/OpenVideoHarness/releases/download/media/styles-gallery.mp4) 已经是这个结构的雏形，只差一个贯穿的主角。
- 静音：本仓库的底线禁止片中出现数字静音（来自介绍片 v2 被听成"卡住"的教训），复刻时做成屏息：留一层低音垫，镜头慢漂，不要声画一起停死（`playbook/04-audio.md`、TASTE_CHECKLIST #18）。

## 5. Tesseract for design（Mirage）

**类型**：16:9 横屏产品发布片，31.3 s；声音没有量。
**来源**：[X](https://x.com/trymirage/status/2105314048766033999)，Mirage 官方账号，2026-09-30 发布，页面标注"由 AI 生成"。10-01 时 11.1 万浏览。
**产品**：Tesseract 是给 AI agent 用的创作运行时，让 agent 先做设计系统（字体、颜色、版式），再加动效、素材和声音，做成可以逐层修改的视频。贴文说支持 Opus 5.5 和 GPT-6 Astra，免费。[产品页](https://mirage.app/tesseract)（2026-10-02 查）说它是免费的创作引擎，agent 通过插件（ChatGPT）或 skill（Claude 等）接入，也能本地运行；没写许可证。

### 画面拆解

| 时间 | 画面 |
|---|---|
| 0–3.5 s | 云海压在沙漠上，黄昏时一个铬面立方体悬在沙丘上空 |
| 5–8 s | 立方体展开成一叠起伏的图层，再拉开成爆炸图，每层带标签（纹理、阴影、高光、渐变） |
| 9.5 s | 组件页：立方体的各种变体 |
| 11–23 s | "Design System" 看板：拖入灵感图、分享颜色（紫、蓝、橙三个色值）、设定字体、做 logo；输入框里打出一句风格描述；镜头在卡片之间滑动，灵感图里的场景从黄昏变到夜晚 |
| 24.5–26 s | 一张卡片变成金色沙漠的视频，全屏，带时间码，字幕大意是"好视频始于好设计" |
| 27–31 s | 镜头拉远：视频在一台老 CRT 显示器里，屋子很暗；屏幕换成彩虹渐变上的产品名 |

**视觉系统**：胶片颗粒，紫、蓝、橙三色，衬线展示字，深色半透明 UI 卡片，铬面材质。

### 为什么有效

1. **产品的工作流就是叙事**：灵感 → 颜色 → 字体 → logo → 一句 prompt → 视频，正好是产品要卖的流程。
2. **一个主体走完全程**：铬立方体从开场的风景、到图层爆炸图、到设计系统里的素材、再到成片，观众一直跟着同一个东西。
3. **结尾的元叙事**：拉远发现视频在一台显示器里，"这是做出来的作品"。开场的沙漠和立方体，也就这样成了成片里的画面，首尾接上了。

### 用本仓库复刻

- 类型：`video-types/03-product-promo.md`。
- 和本仓库流程的对应：Mirage 卖的"先做设计系统再做动效"，就是我们阶段 2 的 STYLE.md 加 `styles/` 预设。区别是它把设计系统做成了一张**看得见的看板**（灵感图、色板、字体、logo），而我们的 STYLE.md 是文字。

## 五支片子的共同点

1. **先有立意，再有风格**。五个装置：时间放大镜、机器视角的肖像、用做法讲做法、吉祥物穿越风格、工作流即故事。从成片看，风格都在服务装置：要慢放所以有计时 HUD；要私人所以是暖黑和宋体；要展示做法所以每段换一种技术。创作顺序从成片看不出来。
2. **一个贯穿的主体**：彩色 token、字符画人像、橙色小球和公式、吉祥物、铬立方体。这和 BRIEF 里的 Recurring motif 是一回事。
3. **具体的东西**（第 1–3 支）：毫秒读数、具体的计数和原话、帧数。越具体越可信。
4. **首尾呼应**：五支都有，各节里写了呼应的是什么。
5. **prompt 很短，给的是角色、材料和自由**。公开了 prompt 的两支（第 2、3 支），作者给的是：一个视角或角色（在你眼里我是谁；展示你作为动效设计师的实力）、足够的材料（全部记忆和文档）、一两条必须做到的事（一句开场白、30 秒、二维加三维），其余"由你决定"。云野FLOW 那条还明确不让它调用预设的 skill。

## 和本仓库规则的出入

下面这些地方，按我们现在的 `TASTE_CHECKLIST.md` 和 BRIEF 默认值逐条判，会被判失败或需要返工。列在这里是为了看清楚哪些规则是底线、哪些只是一种口味。#10 只管"并非刻意"的用法，下表按"如果没有立意撑着"来判；取样稀疏，#14、#18 只是线索：

| 片子 | 做法 | 会撞到的规则 |
|---|---|---|
| 我眼中的你 | 段落之间从黑场慢慢淡入；一个画面常停 6–15 s | #14（不用 crossfade；从黑场淡入严格说不是 crossfade，算擦边）、#18（讲解类 8 s 无事发生）、`playbook/03` §6 "不用没有承载物的 crossfade"（当时还写在 BRIEF 模板的 Motion defaults 里） |
| FunTech | 霓虹、铬面、多个饱和色；终场前约 1 s 真静音 | #9（强调色不止一个）、#10（霓虹）、#18 和底线"片中不出现数字静音" |
| Mirage | 半透明玻璃感 UI 卡片；紫、蓝、橙三个强调色 | #9、#10（玻璃拟态） |
| 云野FLOW | 四角等宽小读数 | #20（通用 AI 装饰） |
| 科了个喵 | 常驻 HUD，但每个读数都在变、都有意义 | 基本不撞 |

这些片子在各自的语境里都成立。撞到的大多是口味类的条目；底线这边，取样里只看到 FunTech 那 1 s 数字静音，其余底线（每帧是 t 的纯函数、闪白频率、字号）没有逐项核对。怎么调整规则，是另一件事，不在本文里定。
