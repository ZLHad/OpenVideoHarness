## 关卡 ① 大纲（BRIEF 写完后）

**审阅包**（在对话里给出，不超过一屏）：
- 一句话：这支视频讲什么、给谁看、多长、什么画幅、有没有声音；
- 大纲：按时间分成 3–7 段，每段一句话，写清观众看完这段会知道什么；
- 风格：2–3 个参考作品，加 1–2 个明确不要的；
- 引擎选择和理由；需要付费 API 或下载模型的地方，要单独列出并估算费用；
- 需要人拍板的问题：不超过 3 个。

## 关卡 ② 分镜（STORYBOARD 写完后，写场景代码前）

**审阅包**：
- `STORYBOARD.md` 的镜头表，每行包括时间、画面、事件、reads、转场；
- **分镜预览图** `out/check/storyboard.png`：每个镜头一张关键帧，拼成一张图。可以是低清草图、灰盒线框，也可以是关键姿势的静帧（p5 用 `render.mjs --sheet`，HyperFrames 用 `snapshot`，Manim 用 `-ql -s`）。目的是让人**看图**就能判断构图和节奏，不用读长文；

## 授权跳过怎么记

只有用户本人在对话里明确说不用审，才能跳过；协调者或别的 agent 转述的不算。在每道被跳过的关卡的"决定"下写：

```text
- 用户授权跳过（YYYY-MM-DD）。原话："……"（逐字照抄，不转述）
- 范围：跳过关卡 ②③（或：只跳过关卡 ③）
- 代审：独立 reviewer 共 N 轮，每轮结论和打分层的分数见 NOTES.md
- 成片仍待用户本人观看，看完的意见记在本关卡下
```

## 审阅意见怎么写（给人看的提示）

最有效的意见带时间点和原因，例如"0:12–0:15 字太多读不完"或"第 3 镜太静，想要镜头推进"。

"感觉不对""不够炫酷"也可以说。agent 会做一次 look-dev：挑一段 10–20 s 的代表性片段，只改一个预设变量（例如特效强度 A / B / C），渲出 2–3 个变体，附一张同一时刻逐行对照的联系表。你挑一个，它再按这个方向做全片。让人从几个选项里选，比让人描述想要什么更有效，这也是 Paper2Video 的结论。
