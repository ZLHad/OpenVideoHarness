## 审阅页

每次停下来都做一页：写 `out/review/gate-<n>.json`，运行 `bin/vh review <project> <n>`，得到本地页面 `out/review/gate-<n>.html`（最新的一页另存一份 `index.html`），图、GIF、mp4 和音频在浏览器里直接看、直接听。`<n>` 是关卡 `1` `2` `3` 或检查点 `E0`–`E5`，同一处的第二页加 `b`（`2b`）。聊天里只发命令打印的那几行：要人定的事、照推荐的整句回复、页面路径。

页面从上往下：
1. **要你定的 ≤3 件事**（第一屏）：问题、推荐和一句理由、改动成本（"现在改：低 · 分镜后改：高"）、怎么回（`H1 / H2 / H3`）。最后是照推荐的整句回复（`1 H2 · 2 A · 3 通过`）。其余默认通过。
2. **图**：每个决定配图，每张一行说明。选项并排成一张图（钩子 3 行 × 3 帧，封面加信息流大小的缩略图）；声音给试听文件，agent 听不见的地方明说。
3. **选项**：一张小表，每个选项一行，写好处和代价。
4. **分段页**（分镜）：按大纲一段一页，每页 3–6 镜：关键帧、这一段的 animatic、没把握的镜头标红并写一句为什么；逐镜表默认全部通过，人只写要改的（`S04 改：……`）。
5. **附录**（折叠）：reads 时间表、转场、实现方式、出处，凡是不影响拍板的都放这里。

写完问自己：人 3 分钟内能不能看完第一屏并回复？不能就砍。

| 页 | 要人定的（≤3，按依赖顺序） | 图 | 放附录 |
|---|---|---|---|
| ① 大纲 | 风格（2–3 个预设），加 1–2 个真正影响制作的问题 | 候选风格同一时刻的对照图、大纲时长条 | 引擎和费用明细、参考 |
| E0 / E1 | 这时能定的 `own`：主角、主旋律、旁白稿、钩子 | 设定图、谱面加试听、钩子 3 × 3 帧、旁白时长表 | 实现方式 |
| ② 分镜 | 还没定的 `own`，加 agent 自己拿不准的取舍 | 分段页、节奏图、animatic | reads 时间表、转场 |
| ③ 初版 | 放行：通过 / 改（写时间点）/ 说不清就先做 look-dev | draft、整片联系表、最不满意的 2–3 处的截图 | 自查和打分记录、事实出处 |

### 审阅包 JSON：`out/review/gate-<n>.json`

`bin/vh review` 和以后的界面都读它。路径相对项目目录。

```json
{
  "gate": "2",
  "summary": "24 镜分 6 段；先定主角、主旋律、钩子，约 5 分钟",
  "decisions": [
    {"id": "hook", "question": "前 3 秒用哪个钩子？",
     "options": [{"id": "H1", "label": "反常识数字", "pro": "一句话就是结论", "con": "画面抽象"},
                 {"id": "H2", "label": "冲突画面", "pro": "最抓眼，是真事", "con": "要控制白闪"}],
     "recommend": "H2", "why": "你在关卡 ① 倾向它", "cost": "现在改：低 · 只动 0–11 s", "reply": "H1 / H2"}
  ],
  "assets": [{"path": "out/review/hook-options.png", "caption": "每行一个钩子：0.4 / 1.4 / 2.9 s", "for": "hook"}],
  "least_sure": [{"id": "S02", "note": "白闪 0.1 s 会不会刺眼；默认保留 1 次"}],
  "animatic": "out/animatic.mp4",
  "segments": [
    {"id": "1", "title": "钩子", "t0": 0, "t1": 11, "note": "6 刀，平均 1.8 s",
     "shots": [{"id": "S01", "t0": 0, "t1": 1.6, "frame": "out/check/sb/frame-00.png", "see": "两颗卫星相向飞来", "vo": "……"}]}
  ],
  "appendix": [{"title": "reads 时间表", "path": "STORYBOARD.md"}]
}
```

- **必填**：`gate`；`summary`，一句话说这页要你定什么、看完要多久；`decisions`，空列表表示这页只给人过目。每个决定都要有 `question` 和 `recommend`；`reply` 不写就用选项名拼。选项名别用纯数字，免得和决定的编号混在一起。
- **选填**：`why`、`cost`，选项的 `label` / `pro` / `con`；`decided`（已经定了的，一行一条）、`delegated`（这一轮替人定的，细节在 DECISIONS.md）、`not_reviewed`（这页不审什么，例如"灰盒不看质感"）、`title`、`lang`（`zh` / `en`，页面文字的语言）。
- `assets[].for` 写决定或分段的 `id`，图就放在它下面，不写就放进"其他材料"；视频加 `t0` / `t1` 只播一段。写了 `animatic`，每个分段页自动只播自己那一段。
- `least_sure` 里写了镜头号，那一镜就标红。文字里出现的镜头号（`S04`）会链到那一镜。镜头的 `note` 写"默认会这样改"，照样默认通过。
- 决定超过 3 个、决定没有推荐、文件不存在时，命令照样生成页面，但退出码是 1：先改好再发给人。

## 授权跳过怎么记

只有用户本人在对话里明确说不用审，才能跳过；协调者或别的 agent 转述的不算。在每道被跳过的关卡下写：

```text
- 用户授权跳过（YYYY-MM-DD）。原话："……"（逐字照抄，不转述）
- 范围：跳过关卡 ②③（或：只跳过关卡 ③）
- 代审：独立 reviewer 共 N 轮，每轮结论和打分层的分数见 NOTES.md
- 成片仍待用户本人观看，看完的意见记在本关卡下
```

## 给人看的提示

最有效的意见带镜头号或时间点，再加原因，例如"S03 太静，想要镜头推进""0:12–0:15 字太多读不完"。照推荐的整句回复（`1 H2 · 2 A · 3 通过`）直接发回来也行。

"感觉不对""不够炫酷"也可以说。agent 会做一次 look-dev：挑一段 10–20 s，只改一个变量（例如特效强度 A / B / C），渲出 2–3 个变体，附一张同一时刻逐行对照的联系表。你挑一个，它再按这个方向做全片。让人从几个选项里选，比让人描述想要什么更有效，这也是 Paper2Video 的结论。
